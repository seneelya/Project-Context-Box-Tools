# HowTo: тестирование make_interface_card

Живёт здесь, в `__HQ/tools/test/`, рядом с самими тестами. Описывает подход СЕГОДНЯ, будет меняться
по мере работы — не константа.

## Регресс — гонять перед коммитом

```bash
py test/check.py --fails            # оракул по всему пакету tools (не только эта утилита)
py test/test_cardstamp.py           # узкие ассерты: is_empty, merge/salvage/зона/discrepancies
```

`test_cardstamp.py` — программные, самопроверяющие тесты на внутренние функции
(`build_card`, `_parse_old_prose`, `_entry_key`, `_resolve_entry_identities`, `_stamp_to_file`),
на синтетических временных проектах и паре реальных фикстур пакета (`test/pythonSRC/`,
`test/tsSRC/`, `test/unitySRC/`). Быстро, но нечитаемо человеком — ассерт падает строкой, не видом
карточки целиком.

## Ручной полигон merge-идентичности — `test/restamp_fixtures/`

Самая важная и самая хрупкая операция тула — **re-stamp существующей карточки** (merge-режим, без
`--force`): при находке REQ-004+005 это молча стирало ВСЮ написанную человеком прозу на любом
JS/TS/C#/async-Python файле при обычном штатном re-stamp. `test_cardstamp.py` эту логику покрывает,
но её результат не наглядный. Для наглядности и ручной проверки — `restamp_fixtures/`: по паре
«исходник + карточка ДО» на Python/TypeScript/C#, каждая пара одним диффом показывает все пять
исходов merge (не изменилось / сигнатура сменилась / переименовали / удалили / добавили).

```bash
py test/run_restamp_fixtures.py            # все три языка, точки + сводка
py test/run_restamp_fixtures.py --diff     # плюс unified diff "до/после" — читать глазами
py test/run_restamp_fixtures.py python     # только один язык
```

Раннер копирует `sample.<ext>.md` в `.actual/` (гитигнорится) и штемпелит копию — эталон в
`restamp_fixtures/<lang>/` никогда не перезаписывается. После прогона `.actual/` можно открыть
руками. Детали устройства, как добавить язык/сценарий, как проверять порог схожести для новой пары
переименования — `test/restamp_fixtures/README.md` (живёт рядом с самими фикстурами).

## Что нового чинит REQ-004+005 (design — `__dev/Requests/DONE__REQ-004+005_merge-identity-design.md`)

- Имя записи для merge ищется ПО ПОЗИЦИИ в сигнатуре (перед `(`/`=`, иначе после известных слов
  языка), не угадыванием по первому слову текста — старое угадывание ломалось на любой языковой
  обёртке (`function`/`async`/`public static void`) и схлопывало ВСЕ функции файла в один ключ.
- Переименование ловится по похожести имён на остатке несовпавших записей (не по позиции/тексту).
- Расхождение сигнатуры при совпавшем имени НЕ теряет прозу — помечает её маркером
  `⚠ поменялась сигнатура -`, стопкой (без счётчика) при повторных необсмотренных re-stamp'ах.
- `--force` на карточке с уже заполненной прозой требует `--discard-prose` (иначе exit 2, ничего
  не пишется) — было тихой потерей по мышечной памяти.
