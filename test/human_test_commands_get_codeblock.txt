# ============================================================
# get_codeblock — Vision03/04 · canonical order: WHERE -> VERB -> ADVERBS
#   --project-root R  --file F  --line N  (--ancestor-level N | --level N)  (--outline | --dot | --query)  --numbered
#   Address narrows FIRST (root -> file -> line -> block), THEN the verb acts, THEN adverbs.
#   (flags are position-INDEPENDENT; this is the writing convention, not a parser rule.)
#   verbs:    bare/--outline = map (landmarks + file-level filler only) · --dot = same map but
#             filler shown at EVERY level (diagnostic — see what a grep would actually land in) ·
#             --line = ladder (staircase) · --query = pull block text
#   address:  --ancestor-level N = N blocks UP from the line (0=innermost/default, 1=parent). The usual one.
#             --level N          = absolute depth from the file TOP (1=outermost). With --outline/--dot: caps shown depth.
#             (raw --level -N still works, == --ancestor-level N)
#   focus:    (--outline | --dot) --line N [--level K] = expand ONE block (the K-ancestor of
#             line N) as its own map. With --dot the target itself can be a filler leaf (a
#             class field, a top-level import run, …) — see invariant #9 examples below.
# ============================================================
