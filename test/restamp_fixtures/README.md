# restamp_fixtures — полигон для merge-идентичности карточек (REQ-004+005)

Место, чтобы РУКАМИ посмотреть и/или прогнать регресс на самую важную и самую хрупкую операцию
тулинга — **re-stamp существующей карточки** (`make_interface_card.py` без `--force`, merge-режим).
До REQ-004+005 эта операция могла молча стереть всю написанную человеком прозу; закрывающий её
патч и повод для этой папки — см. `__dev/Requests/REQ-004+005_merge-identity-design.md`.

## Что тут лежит

Один язык — одна папка (`python/`, `typescript/`, `csharp/`), в каждой — пара файлов:

- `sample.<ext>` — исходник, каким он ЕСТЬ сейчас;
- `sample.<ext>.md` — карточка, какой она была бы, если бы её написали для **более ранней**
  версии этого исходника, и с тех пор источник поменялся, но карточку не обновляли.

Это НЕ случайные фикстуры — расхождение между файлом и карточкой в каждой паре нарочно собрано
так, чтобы ОДНИМ прогоном показать все пять исходов, которые вообще может дать merge:

| исход | что видно в примере |
|---|---|
| не изменилось | имя+сигнатура совпали дословно → проза переносится как есть, без маркера |
| сигнатура изменилась (та же сущность) | функция стала `async` / класс стал `sealed` — имя то же, проза переносится с `⚠ поменялась сигнатура -` |
| переименовали | `OUR_TOOLS` → `ALLOWED_TOOLS`, `checkValue` → `check_value`, `NetworkTools` → `AllowedNetworkTools` — точного имени нет, но по похожести нашли; проза переносится с `⚠ похоже на переименование, было ...` |
| убрали из кода | запись есть в карточке, в исходнике больше нет → уходит в `## Salvage`, не пропадает молча |
| добавили в код | символа нет в карточке → директива `<|Agent:...|>` на заполнение, как для новой карточки |

Проза в примерах — служебные метки (`PROSE_UNCHANGED`, `PROSE_SIG_CHANGED`, `PROSE_RENAMED`,
`PROSE_REMOVED`), а не осмысленный текст — они должны буквально появиться в выводе, это и
проверяет раннер.

## Как запускать

Из `__HQ/tools/` (или с `--project-root` неважно — раннер сам строит все пути от расположения
фикстур, cwd ни на что не влияет):

```bash
py test/run_restamp_fixtures.py            # все три языка, точки + сводка
py test/run_restamp_fixtures.py --diff     # плюс unified diff "до/после" на каждый язык — читать глазами
py test/run_restamp_fixtures.py python     # только один язык
py test/run_restamp_fixtures.py typescript --diff
```

`sample.<ext>.md` в каждой папке — эталон, раннер его **никогда не перезаписывает**: копирует в
`.actual/sample.<ext>.md` (гитигнорится) и штемпелит копию. После прогона `.actual/` можно открыть
руками и посмотреть на реальный результат — это и есть «место для тестирования», не только
автоматическая проверка.

## Как добавить сценарий/язык

1. Новый язык — новая папка `restamp_fixtures/<lang>/` с парой `sample.<ext>` / `sample.<ext>.md`,
   собранной по той же схеме (5 исходов), и строчка в `_CASES` в `run_restamp_fixtures.py`
   (имена символов на каждый из пяти исходов — файл сам считает остальное).
2. Прежде чем писать «похожие» имена для переименования, проверь порог схожести на реальном
   алгоритме, а не на глаз — он не всегда интуитивен:
   ```bash
   py -c "import make_interface_card as mic; print(mic._similarity('OldName', 'NewName'))"
   ```
   Нужно ≥ `mic._SIM_THRESHOLD` (сейчас 0.6). Пары «убрали» / «добавили» — наоборот, должны быть
   ЯВНО непохожи, иначе fuzzy-match случайно скрестит удалённый символ с новым.
3. Если меняешь сам исходник фикстуры — поправь ОБЕ половины пары (источник и `sample.<ext>.md`)
   согласованно: раннер сверяет их друг с другом, а не с каким-то третьим эталоном.

## Отличие от `test_cardstamp.py`

Там — узкие программные ассерты на внутренние функции (`_entry_key`, `_resolve_entry_identities`)
и синтетические временные проекты, без файлов в репозитории. Здесь — читаемые человеком файлы,
которые можно открыть, поменять руками и посмотреть, что случится при следующем стампе; ценность
именно в наглядности и в том, что три языка проверяются на реальных file+card парах, а не на
собранном на лету тексте.
