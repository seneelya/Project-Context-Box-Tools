# get_codeblock — Vision Contract

## Назначение
Возвращает осмысленный законченный блок кода, содержащий заданную строку файла, для LLM-агентов.

## Аргументы (порядок не важен)

| Флаг | Тип | Обязательный | Описание |
|------|-----|--------------|----------|
| `--file` | string | Да | Путь к файлу (абсолютный или относительный) |
| `--line` | int | Да | Стартовая строка поиска блока |
| `--level` | int | Нет (default 0) | Адрес возвращаемого блока |
| `--query` | flag | Нет | Вернуть текст блока вместо метаданных |
| `--project-root` | string | Нет | Корень для относительных путей. Может быть из tools_config.py; CLI перекрывает конфиг |

Тип языка определяется по расширению файла: `.py`, `.ts`, `.js`, `.cs`.

## Режимы вывода

### Без `--query` (метаданные)
Формат: `Block level: <level> from: <from_line> to: <to_line> lines`

Пример:
```
Block level: 4 from: 71 to: 77 lines
```

### С `--query` (текст)
Выводит текст блока байт-в-байт из файла, без заголовков и номеров строк.

Пример:
```bash
get_codeblock.py --file x.py --line 50 --query
```

## Адресация уровня (level)

**Level 0 (по умолчанию):** блок, в котором находится строка, включая его заголовок + приклеенные сверху комментарии/docstrings.

**Отрицательные значения (-N):** родительские блоки вверх по иерархии.
- `-1` = родитель текущего блока
- `-2` = дедушка текущего блока
- Если предков меньше запрошенного → вернуть самый внешний из доступных

**Положительные значения (+N):** от верха вложенности, содержащей строку.
- `1` = самый внешний блок, содержащий строку
- `2` = следующий по вложенности
- Если N больше реальной глубины → вернуть внутренний блок реального уровня

Схема адресации:
```
       ← -2
    ┌───┴───┐
    │   -1  │
    │ ┌─────┤
    │ │ -1(0)│
    │ │     │
    │ │  → line здесь
    │ │  0   │ ← текущий блок строки
    │ └─────┘
    └───┬───┘
        └──→ -1 (родитель от уровня -1(0))
```

## Обработка блоков по языкам

### Python — indentation-based

**Заголовок блока:** строка с ключевым словом (`def`, `class`, `if`, `elif`, `else`, `for`, `while`, `try`, `except`, `finally`, `with`, `match`, `case`).

**Тело блока:** все последующие строки с отступом БОЛЬШЕ заголовка, до первой строки тем же или меньшим отступом.

Считаются ВСЕ блоки любого типа.

### Комментарии и docstrings

Комментарии/docstrings приклеиваются к блоку:

| Ситуация | Правило |
|----------|---------|
| Внутри тела блока | Принадлежит этому блоку |
| Перед заголовком на том же отступе (без пустых строк между ними или только с пустыми строками) | Включается в блок как преамбула |
| Docstring сразу после заголовка | Часть блока |

**Важно:** если строка — чистый комментарий и стоит перед блоком на уровне этого блока → возвращается сам блок + этот комментарий. Если строка между блоками без явной привязки → fallback к ближайшему блоку (вверх или вниз), комментарии не учитываются как самостоятельные блоки.

### TypeScript / JavaScript — brace-based `{}`

Блок = область внутри `{ ... }`. Учитываются все конструкции с фигурными скобками. Строковые литералы и шаблонные строки игнорируются при подсчёте вложенности.

### C# — brace-based + regions

Как TypeScript, плюс `#region` / `#endregion` считаются блоками.

## Поведение на граничных случаях

- **Строка за пределами любого блока** (indent=0, не def/class/if): fallback к ближайшему блоку вверх или вниз; комментарии не учитываются как блоки
- **Level больше реальной глубины:** вернуть блок реального уровня строки
- **Отрицательный level выше корня:** вернуть самый внешний доступный блок
- **Ошибка файла/строки/синтаксиса:** явная ошибка в stderr, exit code ≠ 0

## Запуск без параметров

Выводит минимальную подсказку + рецепт запуска.
