# get_codeblock — Vision Contract

## Назначение
Возвращает осмысленный законченный блок кода, содержащий заданную строку файла, для LLM-агентов.

## Аргументы (порядок не важен)

| Флаг | Тип | Обязательный | Описание |
|------|-----|--------------|----------|
| `--file` | string | Да | Путь к файлу (абсолютный или относительный) |
| `--line` | int | Да | Стартовая строка поиска блока |
| `--level` | int | Нет (default 0) | Адрес возвращаемого блока |
| `--query` | flag | Нет | Вернуть текст блока вместо метаданных |
| `--project-root` | string | Нет | Корень для относительных путей. Может быть из tools_config.py; CLI перекрывает конфиг |

Тип языка определяется по расширению файла: `.py`, `.ts`, `.js`, `.cs`.

## Режимы вывода

Префикс всех метадата-строк — коммент языка (`#` Python, `//` TS/C#), чтобы не мешать парсингу кода.

### Без `--query` — ЛЕСТНИЦА вложенности
Печатает ВСЕ объемлющие блоки, от строки наружу (внутренний → внешний), по строке на блок.
Один вызов = все варианты зума; дальше выбираешь `--level` и делаешь `--query`.
```
#Block level: 3 range: 139-145
#Block level: 2 range: 137-161
#Block level: 1 range: 94-172
```

### С `--query` — блок в обрамлении якорей
Заголовок + тело байт-в-байт + футер. Обрамление позволяет лить несколько блоков подряд
(в файл/контекст) не сливая их, и точно видеть, куда патчить. `--level` выбирает блок из лестницы
(default `0` = внутренний).
```
#Block level: 3 range: 139-145
        <тело блока байт-в-байт>
#Block end: 145
```
Имя файла в вывод НЕ включаем (агент и так знает файл; это не «долгая» информация).

### `--outline` — оглавление структуры (без `--line`)
Печатает **только именованные** блоки файла (заголовки в MD; `def/class`/методы в коде —
управляющие блоки `if/for` НЕ включаются), иерархически, с ренджем и меткой. `--level` режет
глубину. Так агент находит нужную строку, потом тянет раздел `--line N --query`. Формат строки:
`<prefix>Block level: N range: X-Y — <метка>`. Конец секции = строка перед следующим блоком того
же/меньшего уровня (точно для TOC; точные границы — через `--query`). Реализовано: MD, Python
(TS/C# — следующим заходом под тесты). Хендлер даёт `outline()`, когда поддерживает.

## Языки
- **Python** — по отступам; **TS/JS, C#** — по `{}` + безскобочные `if/for` по отступу;
- **Markdown** (`.md`/`.markdown`) — секции по ATX-заголовкам, **level = глубина заголовка (без +1)**,
  фенсы ` ``` `/`~~~` пропускаются. Лучше всего с `--outline`.
- Каждый хендлер владеет своей нумерацией: `line_level` + `get_blocks` (+ `outline` где есть).

## Нумерация уровней (депт) — ДВЕ разные оси

Есть два разных смысла числа «level», их нельзя путать:

1. **Глубина блока (реальный уровень):** `level = 1 + число объемлющих ТЕЛ блоков`.
   Корень файла = **1** (сам файл не нумеруем). Заголовок блока (`if/for/def`, включая
   многострочную сигнатуру) принадлежит телу РОДИТЕЛЯ и стоит на его уровне; тело блока —
   на 1 глубже. Реальные уровни — только натуральные `1,2,3,…`; **`0` реальным уровнем не
   бывает** (строка на корне = 1, не 0). Для brace-языков «тело» = внутри `{…}`; безскобочный
   `if/for/while` (тело — следующая строка) считается по отступу. Docstring/коммент наследует
   уровень ближайшего примыкающего кода с меньшим уровнем (приклеен к заголовку).
   Это то, что отдаёт `get_line_levels` (и показывает `codebase_import_search` в `levels=`).

2. **Адресация `--level` (навигация):** это НЕ глубина, а указатель для выборки блока.

**Level 0 (по умолчанию):** блок, в котором находится строка, включая его заголовок + приклеенные сверху комментарии/docstrings.

**Отрицательные значения (-N):** родительские блоки вверх по иерархии.
- `-1` = родитель текущего блока
- `-2` = дедушка текущего блока
- Если предков меньше запрошенного → вернуть самый внешний из доступных

**Положительные значения (+N):** от верха вложенности, содержащей строку.
- `1` = самый внешний блок, содержащий строку
- `2` = следующий по вложенности
- Если N больше реальной глубины → вернуть внутренний блок реального уровня

Схема адресации:
```
       ← -2
    ┌───┴───┐
    │   -1  │
    │ ┌─────┤
    │ │ -1(0)│
    │ │     │
    │ │  → line здесь
    │ │  0   │ ← текущий блок строки
    │ └─────┘
    └───┬───┘
        └──→ -1 (родитель от уровня -1(0))
```

## Обработка блоков по языкам

### Python — indentation-based

**Заголовок блока:** строка с ключевым словом (`def`, `class`, `if`, `elif`, `else`, `for`, `while`, `try`, `except`, `finally`, `with`, `match`, `case`).

**Тело блока:** все последующие строки с отступом БОЛЬШЕ заголовка, до первой строки тем же или меньшим отступом.

Считаются ВСЕ блоки любого типа.

### Комментарии и docstrings

Комментарии/docstrings приклеиваются к блоку:

| Ситуация | Правило |
|----------|---------|
| Внутри тела блока | Принадлежит этому блоку |
| Перед заголовком на том же отступе (без пустых строк между ними или только с пустыми строками) | Включается в блок как преамбула |
| Docstring сразу после заголовка | Часть блока |

**Важно:** если строка — чистый комментарий и стоит перед блоком на уровне этого блока → возвращается сам блок + этот комментарий. Если строка между блоками без явной привязки → fallback к ближайшему блоку (вверх или вниз), комментарии не учитываются как самостоятельные блоки.

### TypeScript / JavaScript — brace-based `{}`

Блок = область внутри `{ ... }`. Учитываются все конструкции с фигурными скобками. Строковые литералы и шаблонные строки игнорируются при подсчёте вложенности.

### C# — brace-based + regions

Как TypeScript, плюс `#region` / `#endregion` считаются блоками.

## Поведение на граничных случаях

- **Строка за пределами любого блока** (indent=0, не def/class/if): fallback к ближайшему блоку вверх или вниз; комментарии не учитываются как блоки
- **Level больше реальной глубины:** вернуть блок реального уровня строки
- **Отрицательный level выше корня:** вернуть самый внешний доступный блок
- **Ошибка файла/строки/синтаксиса:** явная ошибка в stderr, exit code ≠ 0

## Идея использования (recipe) — «пристрелка», не читая файл

Задача агента: достать **один самодостаточный блок** из большого (вплоть до 600 КБ) файла, не читая его целиком.

Ключ: **вызов без `--query` = бесплатная пристрелка** (только метаданные `level`+`range`, токены на текст не тратятся). Метадату можно снимать на ЛЮБОМ уровне.

**Первый выстрел — сразу на самый крупный объект `--level 1`** (НЕ голый `--line`: голый даст мелкий блок level 0, где физически сидит строка). Дальше сужаем:

```
--line 69 --level 1            → range 1-600   верхний объект огромен
--line 69 --level -1           → range 40-95   шаг от строки чуть шире — в самый раз
--line 69 --level -1 --query   → достаём текст
```

Две системы отсчёта — под две задачи, оба «дай больший законченный блок»:
- **`+N` (от корня вниз):** `+1` = самый крупный самодостаточный объект вокруг точки. Основной приём — вытащить весь объект, где сосредоточены вызовы.
- **`0` / `-N` (от строки вверх):** шаг за шагом расширяем контекст вокруг места использования/ошибки, когда весь верхний объект избыточен.

Один и тот же блок может иметь два имени (`+2` ≡ `-1`) — это не баг, а две линзы.

Зачем: типовой вход — список строк-вызовов из `codebase_import_search` (`lines=[..] levels=[..]`). По ним пристреливаемся и забираем ровно нужный блок. `M` (макс. глубина файла) агенту не нужен: своя глубина уже дана числом `level`, а зумим всегда наружу.
