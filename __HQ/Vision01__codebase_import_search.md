# codebase_import_search — Vision Contract

## Назначение
Даёт **факт**, а не догадку: кто в проекте реально импортит целевой файл и какие символы из него тянет. Закрывает дыру «consumed surface» — карточка по одному файлу видит только исходящую сторону (что файл экспортит/импортит), но НЕ знает, что из него реально потребляют снаружи. Это входящая сторона, собираемая механически по импортам всего проекта.

## Режимы (через задачу агента)
- **default (downstream consumers)** — ЧТО из файла реально используется вовне = его настоящий внешний интерфейс. Группировка по файлам-потребителям с типом загрузки.
- **`--incoming` (upstream)** — ОТКУДА файл берёт зависимости; внешние пакеты/stdlib сгруппированы как `[external]`.
- **`--verbose`** — ГДЕ именно каждый символ: файл, точные строки, тип загрузки, глубина блока (`lines=[..] levels=[..]`). Это и есть вход для пристрелки `get_codeblock` (см. его Vision).
- **`--tests-only`** — какой API покрыт тестами (сравнение с продовым сканом = непокрытые символы).

Маркеры load-type: `top-level` / `lazy` / `conditional` / `fallback` / `Possible Dynamic import`.

## Связь с get_codeblock
`--verbose` отдаёт `lines=[..] levels=[..]` → агент пристреливается `get_codeblock`-ом и вытаскивает ровно нужный блок, не читая файл целиком. Две руки работают в паре.

## Решения по доводке (locked)

### 1. Семантика пустых символов — БАГ
Сейчас в `--verbose` встречаются символы с пустым телом (`_RERANK_PROVIDERS:`, `_rerank_once:`) — их никто не импортит, но они в списке и в счётчике `unique symbols`. Гипотеза: список символов взят до фильтрации / просочились имена из докстрингов (остаток ранее чиненного бага). 
**Решение:** символы, которые реально никто не тянет, НЕ попадают в список потребления и в счётчик `unique symbols`. Если захотим показывать «мёртвый публичный API» — это **отдельная явная группа** (`dead / no consumers`), не пустая строка.

### 2. Нормализация путей → всегда `/`
Вывод сейчас даёт нативный разделитель ОС (`_engine\backends\chat.py` под Windows-докером агента). 
**Решение:** канон — **всегда `/`** во всём, что тул печатает и что мы храним (склейка с картой `File Path`, кросс-ОС: карточку пишут под Linux, читают под Windows). Это нейтральный факт, а не «выбор Linux»: Python-`open()` жуёт `/` на Windows, git хранит `/`. Нативный `\` — только на границе вызова ФС (Python почти никогда не требует). Завести **глобально** (общий util / `tools_config`), не в каждом хендлере.

### 3. Счётчик саммари должен совпадать с телом
`# N files, M unique symbols` обязан считать только реально потребляемые символы (следствие решения 1).

## Архитектура (справочно)
`LanguageHandler(ABC)` + хендлеры по языкам (`python_handler` / `ts_handler` / `csharp_handler`), реестр `get_handler(lang)`. regex, не AST. Языки: Python / TypeScript-JS / C#. Дефолты из `tools_config.py` (`PROJECT_ROOT`, `LANGUAGE`, `TEST_DIRS`), CLI перекрывает.
