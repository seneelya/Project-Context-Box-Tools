# get_codeblock — БАГ #1: glue-комментариев захватывает чужой код через подвесные комментарии

Дата обнаружения: 2026-08-19. **Статус: ✅ ИСПРАВЛЕН 2026-08-19** (см. раздел «Реализованный фикс» ниже). Воспроизводился стабильно.
Обнаружен при проверке гарантии «диапазон читает только целые блоки» перед интеграцией get_codeblock в нативный read.

## Симптом

`--query` возвращает блок с чужими строками кода, вшитыми сверху:

```ts
// /tmp/repro_glue.ts (весь файл)
1  if (z) { log(z) }   // trailing A
2  if (q) { log(q) }   // trailing B
3  (пустая строка)
4  function gamma() {
5      return 1;
6  }
```

Команда: `get_codeblock.py --file /tmp/repro_glue.ts --line 5 --query`

Фактический вывод (реальный, 2026-08-19):

```
//File: /tmp/repro_glue.ts
//Block level: 1 range: 1-6  function gamma()      <- ДОЛЖНО БЫТЬ 4-6
if (z) { log(z) }   // trailing A                  <- чужой код захвачен
if (q) { log(q) }   // trailing B                  <- чужой код захвачен

function gamma() {
	return 1;
}
//Block end: 6
```

Контроль (без подвесных комментариев, та же структура): блок `delta()` на строках 3–5 возвращается как `range: 3-5` — корректно. Т.е. виновны именно подвесные комментарии + пустая строка между ними и блоком.

Почему критично для нативного read:
1. Нарушается гарантия «целые блоки» — содержимое блока молча расширяется вверх и включает чужой код.
2. Якоря/нумерация смещаются: модель видит `range: 1-6`, а функция реально начинается на строке 4 → любая дальнейшая адресация по этим координатам ошибочна.
3. Эффект накапливается: цепочка подвесных комментариев может дотянуть блок до начала файла (в репро — так и произошло).

## Корневая причина (по коду)

Файл: `__HQ/tools/get_codeblock/handlers/_treesitter_blocks.py`

1. `_comment_rows(root)` — строки **140–146**:
   ```python
   @staticmethod
   def _comment_rows(root):
       rows = set()
       for n in _walk(root):
           if n.type == 'comment':
               for r in range(n.start_point[0], n.end_point[0] + 1):
                   rows.add(r)
       return rows
   ```
   Множество строк, где есть **любой** comment-узел tree-sitter. Подвесной `// trailing A` в конце кодовой строки попадает сюда — строка помечается «комментарная», хотя она одновременно и кодовая.

2. `_preamble_start(start_row, comment_rows, lines)` — строки **149–161**:
   ```python
   @staticmethod
   def _preamble_start(start_row, comment_rows, lines):
       first = start_row
       r = start_row - 1
       while r >= 0:
           if not lines[r].strip():      # (а) пустые строки ПРОПУСКАЮТСЯ без остановки обхода
               r -= 1
               continue
           if r in comment_rows:         # (б) «комментарная» строка → продолжаем вверх, first = r
               first = r
               r -= 1
               continue
           break
       return first
   ```
   Обход вверх от начала блока: пустая строка не останавливает поиск ((а)), строка с подвесным комментарием считается «комментарной» по (б) — и обход улетает дальше. В репро: от `gamma()` (строка 3, 0-based) вверх → пустая пропущена → строка 2 (`if ... // B`) «комментарная» → строка 1 (`if ... // A`) «комментарная» → r = -1 → `first = 0` → start = 1.

3. Единый расчёт границ `_bounds(node, bodies, comment_rows, lines)` — строки **205–213** (коммент в коде: "THE range of a block node — identical in every mode"):
   ```python
   return {
       'level': self._level_of_row(node.start_point[0], bodies),
       'start': self._preamble_start(node.start_point[0], comment_rows, lines) + 1,
       'end': node.end_point[0] + 1,
   }
   ```
   Значит баг бьёт на **все** режимы сразу: outline (строка ~227 `outline()`), ladder (`line_level`/`get_blocks`, строки 245–274), query — везде один и тот же `start`.

## Почему фича «док-коммент приклеивается к блоку» ломается именно так

Назначение `_preamble_start` (по комментам в коде, строки ~163–175, 205–213): ведущий комментарий над блоком должен «приклеиться» к нему. Для нормального ведущего комментария логика верна — проверено:

```ts
// doc comment          <- заголовок блока, только comment-узел
function beta() { ... }
```
→ `range` начинается с коммента. Корректно.

Слом возникает на пересечении двух условий: строка покрыта и кодом, и подвесным комментарием (tree-sitter даёт comment-узел внутри/после выражения), И между ней и блоком есть пустые строки, которые обход пропускает.

## Предложенный фикс (языково-независимый)

Вместо «строка содержит любой комментарий» требовать «строка покрыта **исключительно** комментариями»:

1. В `_comment_rows` (или рядом) собрать дополнительно `code_rows` — строки, покрытые любыми НЕ-comment узлами дерева:
   ```python
   @staticmethod
   def _preamble_row_sets(root):
       comment_rows, code_rows = set(), set()
       for n in _walk(root):
           rows = range(n.start_point[0], n.end_point[0] + 1)
           if n.type == 'comment':
               comment_rows.update(rows)
           else:
               code_rows.update(rows)
       return comment_rows, code_rows - comment_rows   # чистые кодовые строки
   ```
2. В `_preamble_start` (строка 156) условие «комментарная строка» заменить на:
   ```python
   if r in comment_rows and r not in code_rows:
   ```
   Подвесной комментарий: строка покрыта и if-выражением → в `code_rows` → glue останавливается. Ведущий коммент: только comment-узел → чистая → приклеивается как задумано.

Альтернатива (меньше правок): не пропускать пустые строки, если выше них уже была «комментарная» строка, покрытая кодом — но это хрупче и не лечит корень.

## Реализованный фикс (2026-08-19) — с важной поправкой к предложению выше

Фикс сделан **одним методом** `_comment_rows` (строки 139–146), без протягивания `code_rows`
через сигнатуры `_preamble_start`/`_preamble_owner`/`_bounds`: `comment_rows` теперь возвращает
строки, покрытые **исключительно** комментариями, а все три места-потребителя (`_preamble_start:156`,
`_preamble_owner:170`, роутинг в `get_blocks:265`) автоматически получают верную семантику.

**Поправка к предложению из раздела выше:** наивное `comment_rows - code_rows` по ВСЕМ узлам дерева
(как в черновом `_preamble_row_sets`) — **ломает штатную приклейку ведущего док-коммента**.
Контейнерные узлы (`program`, тело класса) спанят строки ведущих комментариев → те попадают в
`code_rows` → вычитаются → ведущий `// doc` перестаёт приклеиваться (проверено вживую: `beta` дал
`2-4` вместо `1-4`). Решение: считать `code_rows` **только по листовым узлам** (`n.child_count == 0`)
— лист несёт реальный токен на строке, контейнер только охватывает диапазон.

```python
@staticmethod
def _comment_rows(root):
    comment_rows, code_rows = set(), set()
    for n in _walk(root):
        if n.child_count:          # только ЛИСТ несёт реальный токен на строке;
            continue               # контейнер спанит строки комментариев и ложно
        rows = range(n.start_point[0], n.end_point[0] + 1)  # пометил бы их кодом
        if n.type == 'comment':
            comment_rows.update(rows)
        else:
            code_rows.update(rows)
    return comment_rows - code_rows
```

**Верификация:**
- Репро `gamma()`: `range: 4-6` ✅ (было 1-6 с двумя чужими строками).
- Приклейка ведущего коммента сохранена: `beta` (первая строка файла) → `1-4`, `beta2` (середина) → `10-13` ✅.
- Обобщение по языкам: тот же glue-паттерн в `.js`/`.cpp`/`.cs` → `4-6` ✅.
- Регрессия на edge-фикстурах: `--outline` всех 8 файлов (`Component.tsx`, `Edge.{cpp,cs,h,js,py,scss,ts}`) — **идентичен** до/после (outline печатает `range` каждого блока → границы не поехали).

## Затронутость других мест (проверено)

- `handlers/python_handler.py:294–323` (`collect_preamble`) — **НЕ затронут**: там комментарий признаётся только по `content.startswith('#')` / `"""` / `'''`, т.е. подвесной коммент в конце строки не считается. Пустые строки пропускает (строка 309–311), но без кодового «моста» обход останавливается на первой не-комментарной строке.
- Markdown-хендлер — не использует glue по комментариям (блоки по заголовкам).
- Точки вызова `_preamble_start` в `_treesitter_blocks.py`: строки 171 (`_preamble_owner`), 212 (`_bounds`). Обе проходят через один фикс.

## Влияние на текущее использование (оценка)

На практике баг срабатывает, когда над целевым блоком есть пустая строка И выше неё — кодовые строки с подвесными комментариями. В типичном коде «док-коммент → блок» без кода между ними — не проявляется. Вероятность в реальном репо: средняя (подвесные комментарии часты). Для гарантии целых блоков в нативном read фикс обязателен до интеграции.
