## Поведение и границы исправления

Пустая строка внутри уже приклеенной комментарной преамбулы именованного блока
получает владельца полной карты. Пустые строки перед первым настоящим комментарием,
после блока и внутри строковых литералов не притягиваются к следующему определению.
Правка общая, без if lang == … и без новых грамматик/зависимостей.

Brace-адресация сохраняет настоящих предков/control-блоки и добавляет канонического
именованного владельца, включая определения без собственного тела. Источник истины
— Classifier полной карты через общий classify.blank_preamble_at. Это существенно:
сырой focus-selector может ошибочно считать хвостовой комментарий предыдущего
оператора началом следующей преамбулы; проверка по полной карте этого не делает.

У определения без собственного тела внутри контейнера сохраняется внешний rung,
а не подменяется вся лестница одной строкой. Старый leaf-fallback для пустой строки
не используется, если полная карта не подтверждает владельца: так исключается
ложное приклеивание до первого настоящего комментария.

Python тоже воспроизводил дефект. collect_preamble оставлен источником начала;
пустая строка направляется в его def/class/async-def только при попадании в диапазон
преамбулы. Учитывается многострочный стек декораторов; in-string mask исключает
пустые строки внутри многострочных литералов. Непустой путь не менялся.

Три места конвенции НАЧАЛА:

1. _preamble_start/collect_preamble не меняют начала уже существовавших блоков.
2. Classifier/pending и полный outline не менялись.
3. Focus на целевой пустой строке использует каноническое начало полной карты,
   не выбирает соседнее определение по его ложному inline-comment префиксу.
