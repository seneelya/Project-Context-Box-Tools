# Plan03 — Runtime seams: machine-readable table + section rename

Основа: `Vision07__runtime-seams.md` (все решения см. там; здесь — порядок реализации).

## Пункт 0 — переименование секций (тот же version-бамп)

`Dependencies Internal` → `In-Project Dependencies`, `Dependencies External` → `External
Dependencies` в `H2_SECTIONS`. Старые названия остаются читаемыми через `ALIASES` (`canon()` уже
умеет мигрировать legacy-токены — механизм существует, просто добавить 2 записи), так что уже
проштампованные карточки не ломаются при следующем чтении, просто на следующем штампе получают
новый заголовок. Бампнуть `CARD_FORMAT.VERSION`.

## Пункт 1 — словари Kind/Shape в `CARD_FORMAT.py`

- `SEAM_KIND = ["by-path", "process", "http", "file", "event"]` + допустимые суффиксы направления
  (`file:reads|writes|reads+writes`, `event:emits|listens`).
- `SEAM_SHAPE = ["dependent", "equal", "reference"]`.
- Хелперы `is_valid_seam_kind(s)`/`is_valid_seam_shape(s)` — по образцу `is_agent_directive()` и
  соседей, не изобретать новый стиль.
- `SEAM_COLUMNS = ["Target", "Symbol", "Kind", "Shape", "Why"]` — по образцу `DEPS_COLUMNS`.
- `"Runtime seams"` НЕ входит в `H2_SECTIONS`/`H2_SECTIONS_PACKAGE` — секция опциональная,
  появляется только если есть что описывать (тот же статус, что `## Salvage`, не обязательная
  как `Package layout`). Значит `validate_cards.py` не должен требовать её у карточек без неё.

## Пункт 2 — `make_interface_card.py`: рендер + сохранение

- **Если `old_prose` уже содержит секцию `Runtime seams`** — таблица и всё её содержимое копируются
  В ТОЧНОСТИ как есть (та же логика, что уже сохраняет `Package layout`/`Doc links` целиком).
  Единственное исключение — строка-контракт: она узнаётся по фиксированному префиксу (`Contract:`),
  ВЫЧИЩАЕТСЯ при парсинге (тем же приёмом, что уже фильтрует «known submodules...» и глобальный
  `<!-- card-format: ... -->`) и штампуется заново при каждом рендере. Это снимает открытый вопрос
  вижена №2 — механизм уже есть в кодовой базе, просто применить его здесь.
- **Если секции нет** — штамп не создаёт её и не пишет директиву. Вместо этого: если детектор (см.
  пункт 3) нашёл кандидатов в этом файле — короткая строка-хинт в обычном выводе штампа (одна на
  файл, в стиле уже существующих строк `[make_interface_card] --all: ...`).
- Новые флаги: `--help-seams` (без файла, как `--help`, печатает полный контракт секции) и
  `<file> --info-seams` (булевый флаг поверх уже существующего `<file>`/`--file`, печатает найденные
  детектором подозрительные строки в этом конкретном файле).

## Пункт 3 — детектор-сканер (отдельный модуль)

Новый файл (условно `__HQ/tools/seam_scanner.py` или как модуль внутри `get_codeblock`-подобной
структуры — решить при реализации). Держит per-language список regex/строк-паттернов (Python:
`spec_from_file_location`, `subprocess.run`/`Popen`, `os.system`; JS: `import(`, `require(`,
`child_process.spawn`/`exec`; http: `requests.`, `fetch(`, `ctx.rest(`, `axios.`; event: `.on(`,
`.emit(`, `subscribe`/`publish`) — намеренно НЕ исчерпывающий, конфигурация, а не жёсткая логика,
расширяется по находкам. `file`-паттерны сознательно не сканируются (см. Vision07 — слишком много
ложных срабатываний на обычном `open()`). Функция вида `scan(file_path) -> [(line_no, pattern, snippet), ...]`
— чистые данные, ничего не решает про Kind/Shape/Why, это задача агента.

## Пункт 4 — `graph_from_cards.py`

- Парсит таблицу `Runtime seams` со всех карточек (та же табличная механика, что уже читает
  `In-Project Dependencies`, только новый набор колонок и без общего `EDGE_COLUMN` — тут Target
  резолвится в путь ИЛИ остаётся свободным текстом без ребра).
- Рёбра-швы рисуются ОТДЕЛЬНО от импортных (не смешивать в существующих `→`/`←`) — новый маркер,
  подпись `kind — shape`.
- Заметка «the map has N independent parts» в `--discrepancies` учитывает швы — остров, соединённый
  швом, перестаёт быть островом.
- Мермейд-сборка всего проекта из этих строк — отдельный вид (`--view seams-mermaid` или похоже,
  точное имя — при реализации), не блокирует остальное.

## Пункт 5 — `validate_cards.py`

- `Kind`/`Shape` каждой строки — закрытый список (опечатка = issue).
- `Target`, если похож на путь проекта — та же логика `pending`/`unresolved`, что уже есть у
  `In-Project Dependencies` (исходник есть, карточки нет = pending; ни того ни другого = issue).
  Свободный текст вне проекта — не резолвится, не issue, просто заметка.

## Пункт 6 — TLDR

`make_interface_card__TLDR.md` — одна строка про `--help-seams`/`--info-seams`, иначе никто не
узнает, что они существуют.

## Тесты

- Парсинг: секция с реальными строками сохраняется байт-в-байт при повторном штампе, кроме
  строки-контракта (она должна обновиться, если, скажем, поменяли версию контракта).
- Валидатор: строка с левым `Kind`/`Shape` → issue; строка с валидным, но нерезолвящимся
  in-project `Target` без исходника → issue; с исходником, но без карточки → pending.
- Детектор: несколько фикстур-сниппетов на Python/JS с реальными вызовами из списка паттернов —
  проверить, что находит нужные строки и не находит то, чего там нет.
- Граф: синтетические карточки с парой seam-строк — рёбра рисуются, `--discrepancies` не считает
  их соединённые острова отдельными.
- Переименование секций: старая карточка с `## Dependencies Internal` парсится через `ALIASES`
  так же, как раньше — не ломается на переходе.
