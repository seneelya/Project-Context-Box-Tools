## Шаг 1 — кэш сканов `__HQ/tools/_cache/<root>-<hash>/` · ✅

**Итог.** `find_code_usage/scan_cache.py` (языконезависимый `ScanCache`: отпечатки git/mtime,
версия производителя = хеш его исходника, несработавшие файлы выкидываются при записи) +
`Tree.forward` берёт сканы из кэша. Отпечаток конфига не нужен: кэшируется только скан файла,
разрешение include пересчитывается всегда (дёшево, зависит от набора файлов и `CPP_INCLUDE_DIRS`).
Замер llama: дерево 5,2 → 0,35 с; зона 36 файлов 31 → 8 с. Главный выигрыш зоны дал НЕ кэш, а
`cpp_handler.analyze_file`: один проход regex по тексту + предфильтр `set(findall)` ∩ имена цели.
Кэш имён файла («второй потребитель») не понадобился — отложен. Попутно найден и исправлен баг
merge: `#include <…>` в External Dependencies копился на каждой перештамповке (хук `import_line`,
контракт ПОПРАВКА 2; у Шага 3 теперь ПОПРАВКА 3). Тесты: test_cpp 88 → 99.

План был:

- Слой в `find_code_usage/cpp_includes.py` (Tree): загрузка → сверка отпечатков (`git ls-files -s`
  + `git status`; без git — mtime+size) → доскан изменённых → запись. Отпечаток конфига `CPP_*` и
  версия тула в шапке кэша → полный пересчёт при смене.
- Второй потребитель: имена, встречающиеся в файле (для `cpp_handler` — потребители символов).
- `.gitignore` tools-репо: `_cache/`; `deploy_hq._TOOLS_EXCLUDE_PARTS` += `_cache`.
- Тесты: изменить файл → пересканирован ровно он; удалить/добавить; смена конфига → пересчёт.
- Замер на llama: второй прогон зоны 36 файлов — цель в разы быстрее 31 с.

## Шаг 2 — семейства (механически) · ✅

**Итог.** `stamp_langs/cpp.py::families()` + `sections()`. Секция автора = рамка `//`/`// Title`/`//`,
открывающая блок комментария (абзац ВНУТРИ doc-блока — не заголовок; doc ПОСЛЕ рамки допустим —
`llama.h` Sampling API), заголовок ≤60 символов и не предложение. Секции берутся, если их ≥2 с
объявлениями; секция > `FAMILY_BIG`=30 дробится по префиксу `_`-токенов (рекурсивно вглубь,
пока группа >30: ggml → ggml_backend → ggml_backend_sched), группы < `FAMILY_MIN`=4 → «— other
<вид>»; остаток дробления — «other X_*». Без секций — то же по всему файлу; маленький файл —
одно семейство `(whole file)`. Замер: ggml-backend.h 11 (все — секции автора), llama.h 31,
ggml.h 36, ggml-vulkan-types.h 17. Сводка потребителей по семейству — в шаге 3 (её считает
штемпель, у него потребители). Тесты: test_cpp 99 → 106.

План был:

`stamp_langs/cpp.py`: секции-комментарии (рамка `//`/`// Title`/`//`) → префикс имён → вид.
У каждого семейства: имя, объявления, диапазон строк, сводка потребителей по папкам.
Тесты на фикстуре (`ggml-backend.h` — секции автора; `ggml.h` — префиксы).

## Шаг 3 — форма карточки заголовка «API: in source» (`CARD_FORMAT` 1.3.0) · ✅

**Итог.** `CARD_FORMAT` 1.3.0: `API_IN_SOURCE`, `FAMILIES_COLUMNS`, `FAMILY_WHY_SUBSECTION`,
`api_in_source_line/api_in_source_file`. Хук `api_families` (ПОПРАВКА 3). Штемпель: таблица
(«Used from» = объединение потребителей объявлений семейства, свёртка по папкам — общий
`_by_folder` со свёрткой потребителей символа), проза по имени (`_parse_keyed_bullets`),
исчезнувшее семейство и проза старых `####` (карточки до 1.3.0) — в Salvage. Валидатор: маркер
заменяет H4, исходник обязан существовать, колонки фиксированы. Попутно: блоки Salvage без
пустых строк (иначе повторный штамп менял файл). `condition:` у заголовка ушла вместе с
записями — `#if`-зоны остаются в Build facts. fixture `ggml-backend.h`: карточка 82 строки.
Тесты: test_cpp 106 → 111.

План был:

- `CARD_FORMAT`: маркер `API_IN_SOURCE`, подсекция `### What each family is for`.
- Хук модуля языка (контракт `stamp_langs`, ПОПРАВКА 3): язык сам решает форму Public API для
  файла (C/C++-заголовок → «in source» + таблица семейств); штемпель рендерит, не решая за язык.
- Merge: проза семейств по имени (механика `_parse_why_section`); исчезнувшее семейство → Salvage.
- `validate_cards`: Public API с маркером валиден без `####`; названный исходник обязан
  существовать; колонки таблицы семейств — фиксированы.
- Тесты: свежий штамп, merge с прозой семейства, переименованное семейство → Salvage, валидатор.

## Шаг 4 — граф: рёбра из исходников для файлов без карточек · ✅

**Итог.** Хук `source_edges` (ПОПРАВКА 4), `graph_from_cards.add_source_nodes()`: узлы
`card: False` с рёбрами и условиями из скана (`--flags` действуют и на них), карточка остаётся
правдой для своего файла. Только в `--file` (+ `--json` → `no_card`): обзорные виды и
`--discrepancies` остаются по карточкам — там «исходник без карточки» и есть находка *pending*,
подмешанные узлы её бы съели. Больше 8 файлов без карточек в списке — свёртка по папкам (общий
`fold_by_folder`, перенесён из штемпеля). Центр `--file` может быть файлом без карточки.
`--cards-only` — старое поведение. llama: `--file ggml-backend.h` за 0,5 с, `used-by` = 21
карточка + 44 файла без карточек. Тесты: test_cpp 111 → 117.

План был:

`graph_from_cards`: для C/C++-корня — узлы-файлы без карточек из кэша (помечены «no card»),
их рёбра и условия — из скана. `--file` показывает полный `used-by`. Флаг, чтобы выключить
(`--cards-only`) — старое поведение. Тесты: зона из 4 карточек, `used-by` видит файлы вне зоны.
