## Зачем

Vulkan-шейдеры — тот же GLSL с расширениями, и get_codeblock их уже читает. Замер Claude на 185
шейдерах `Y:/SRC/llama.cpp_mix/ggml/src/ggml-vulkan/vulkan-shaders` (`*.comp`, `*.glsl`;
llama.cpp — MIT): sweep 0 HIGH, 368 функций верхнего уровня, но у **118 из 185** файлов в дереве
ERROR/MISSING. Адресация там честная, но грубая. Основные причины (по первой строке ERROR):

| Конструкция | ERROR/MISSING | Пример |
|---|---:|---|
| атрибуты `[[unroll]]`, `[[dont_unroll]]` … (GL_EXT_control_flow_attributes) | ~694 | `add.comp:56` |
| типы с параметрами `coopmat<…>` (GL_KHR_cooperative_matrix) | ~170 | `mul_mm_cm2.comp:752`, `conv2d_mm.comp:226` |
| `tensorLayoutNV<…>`, `tensorViewNV<…>` (GL_NV_cooperative_matrix2) | ~16+ | `flash_attn_cm2.comp:363` |
| хвосты восстановления после них (`}`, `if`, `for`) | остальное | `conv2d_mm.comp:471–478` |

Цифры — ориентир; первым шагом пересчитать точно.

## Решения (не переоткрывать)

- **V1. Механизм — существующий `LangSpec.preprocess`** (как C/C++ `cpp_source.preprocess_bytes`):
  маскировка байтов ДО разбора с сохранением длины и переводов строк — позиции и номера строк не
  сдвигаются, текст блоков берётся из исходных байтов. Никаких `if lang == ...` в движке; грамматику
  не трогаем и не пересобираем.
- **V2. Сначала атрибуты `[[…]]`** — однозначная, дешёвая и самая массовая причина. Затем
  параметры типов `ident<…>` — только если маскировка честная (см. V3); иначе — описать, что
  мешает, и оставить.
- **V3. Честность важнее нуля ошибок.** Маскировка не должна менять, какие строки куда относятся:
  инварианты CONTRACT #6/#7 на каждой строке, ни одна строка не «теряется». Нельзя маскировать
  выражения сравнения (`a < b && c > d`) как шаблон — правило для `<…>` только в позиции типа
  (известные имена типов из расширений: `coopmat`, `tensorLayoutNV`, `tensorViewNV`, … — списком
  данных в профиле, не эвристикой «любое ident<»).
- **V4. Шейдеры владелицы (PlanetWeather) не должны измениться**: 22 файла, 348 функций, прежний
  baseline (`T:/AgentsWork/glsl-wheel-plan10/review-archive/glsl_probe_results_runtime25_2026-11-01.json`)
  и прежний вывод get_codeblock байт-в-байт (сравнить до/после).
- **V5. Фикстуры в репо — синтетические** (своё короткое: `[[unroll]] for`, `coopmat<…>` поля и
  локальные, `tensorLayoutNV`, сравнения `<`/`>` рядом, чтобы ловить ложную маскировку). Код
  llama.cpp в репо не копировать (лицензия разрешает, но правило репо — синтетика). Сырые прогоны —
  вне репо, в `T:/AgentsWork/glsl-wheel-plan10/`.

## Шаги

1. **Замер «до»** на 185 Vulkan-шейдерах: файлов с ERROR/MISSING, число узлов, классификация по
   конструкции (как таблица выше, точно), sweep `--check-query`, число функций.
2. **Атрибуты** (V2): маска `[[…]]` → пробелы той же длины. Учесть: внутри строк/комментариев не
   трогать; `[[` в обычном коде GLSL не встречается иначе (проверить по набору). Замер.
3. **Параметры типов** (V3): маска `<…>` после имени из списка типов расширений. Замер. Если
   приходится угадывать — остановиться, описать, оставить только шаг 2.
4. **Тесты:** синтетическая фикстура (V5) в `test/glslSRC/` + ожидания в `test/expected.py`
   (лестница на строке внутри `[[unroll]] for` — блок цикла, а не ERROR-фрагмент); `test_glsl.py` по
   фикстурам — PASS; ложная маскировка сравнений — отдельная проверка.
5. **Замер «после»** на 185 Vulkan-шейдерах + sweep `--check-query` (HIGH = 0) + все 22 шейдера
   PlanetWeather (V4, байт-в-байт) + полный регресс из `__dev/CONTEXT_RESTORE.md` (числа прежние,
   кроме новых проверок).
6. **Документация:** `reader/CONTRACT.md` (маска GLSL — что и почему), `get_codeblock__TLDR.md`
   (Vulkan-расширения: что понимается), строка в `__dev/DECISIONS.md` и `__dev/TRACKER.md`.

## Готово, когда

- Файлов Vulkan с ERROR/MISSING заметно меньше (цель — атрибуты ушли полностью), sweep HIGH = 0.
- Сравнения `<`/`>` не маскируются (тест).
- PlanetWeather байт-в-байт как до; весь регресс зелёный; в репо — только синтетика.

## Не входит

- HLSL, WGSL, Metal (отложено владелицей до появления реального кода).
- `#include` и раскрытие макросов, своя сборка грамматики.
