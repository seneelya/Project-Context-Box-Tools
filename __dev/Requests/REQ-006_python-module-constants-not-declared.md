# REQ-006 · Python-константы модуля вообще не попадают в карточку

**Тул:** `make_interface_card.py` (`_declared()` python-ветка) / `show_pyfile_api.py` (`collect()`)
**Нашлось:** 2026-08-30, при ручном прогоне `--all` против реального `memohood` (тестирование
патча путей/флагов — REQ-002 и далее). Не связано с той работой, отдельная, самостоятельная находка.
**Статус:** ОТКРЫТ, после компакта.

---

## 1. Суть одной фразой

Модульные константы Python (`KNOWN_SEAMS = (...)` на верхнем уровне файла) не появляются в
карточке НИКАК — ни как факт-запись, ни в Salvage при потере — потому что `_declared()` для Python
вообще не включает их в `exports`, в отличие от JS/TS/C#, где константы — полноценная H3-секция.

## 2. Как обнаружено

Закоммиченная `__map/_core/flags.py.md` в memohood содержала:
```
### Constants
#### `KNOWN_SEAMS` (tuple[str])
consumers 0: (none)
Tuple of seven seam names (...) — documentation and source of truth for defaults in `config.py`.
```
Свежий штамп (`make_interface_card.py _core/flags.py --project-root <memohood>`, без merge) НЕ
выводит эту запись вообще — ни в `### Constants` (такой секции нет вовсе), ни как «утёкший»
consumed-internal. Источник (`_core/flags.py:20`) содержит `KNOWN_SEAMS` реально, `grep` находит.

## 3. Причина (в коде, не гипотеза)

`make_interface_card.py::_declared()`, python-ветка:
```python
exports = [{"name": f["name"], ...} for f in c["functions"]]
exports += [{"name": cl["name"], ...} for cl in c["classes"]]
```
Модульные глобали (`c["module_globals"]` из `show_pyfile_api.collect()`) используются ТОЛЬКО для
`all_defs` (нужен для секции «Consumed internals» — но туда попадают лишь символы, которые
РЕАЛЬНО импортируются извне, `s in consumers`). `KNOWN_SEAMS` в memohood нигде не импортируется
(`consumers 0`), поэтому не проходит и этот путь — исчезает полностью.

Для сравнения: TS/JS/C# ветки `_declared()` строят `exports` из `_declarations()`, где `const`/
`let`/`var` — полноценный `kind`, маппящийся в `_KIND_H3["const"] = "Constants"`. У Python
аналогичного пути для `module_globals` нет вообще.

То, что было в старой карточке memohood — либо ручная правка человека, либо более старая версия
`make_interface_card.py`/`show_pyfile_api.py`, где module-level константы попадали в exports; в
текущем коде такого пути нет.

## 4. Почему это важнее, чем выглядит

Симптом неотличим от «этой константы никогда не было» — карточка не сигналит потерю (не то что
`## Salvage`, вообще молчание). Модульные константы в Python — обычное место для «источника истины»
(ровно как в найденном примере — `KNOWN_SEAMS` документирует набор сим для всего проекта). Проект,
где такие константы есть, получает карточку, которая выглядит полной, но пропускает важный публичный
факт молча.

## 5. Варианты решения (на выбор разработчика)

1. Добавить `module_globals` в `exports` для Python, с `kind="const"` → `_KIND_H3` уже маппит его
   в `"Constants"`, секция появится сама, без правки рендера.
2. Ограничить это ПУБЛИЧНЫМИ константами (не `_`-приватными) — как уже делается для functions/classes
   (`_is_public` в `show_pyfile_api.py`).
3. Решить, нужна ли сигнатура/тип для константы (JS/TS показывают `const X = <value>`) — для Python
   можно показать `NAME = <repr первых N символов значения>` или просто имя, в зависимости от того,
   что полезнее агенту.

## 6. Acceptance criteria

1. `make_interface_card.py _core/flags.py` (или аналогичный файл с публичной модульной константой)
   выводит `### Constants` с записью для неё.
2. Merge (REQ-004+005 механизм) корректно сохраняет прозу такой записи при повторном стампе —
   тест на это должен быть добавлен туда же, где остальные merge-тесты
   (`test/test_cardstamp.py`, возможно `test/restamp_fixtures/python/`).
3. `_`-приватные модульные константы не просачиваются в Public API (кроме случая, когда реально
   потребляются извне — тогда как сейчас, через Consumed internals).
4. Регресс `test/check.py`, `test/test_cardstamp.py` зелёный.

## 7. Чего НЕ просим

- Не просим менять поведение TS/JS/C# — там константы уже работают верно.
- Не просим трогать `all_defs`/Consumed internals — механизм для приватных-но-потребляемых имён
  остаётся как есть, эта находка про ПУБЛИЧНЫЕ константы, которые сейчас теряются просто так.
