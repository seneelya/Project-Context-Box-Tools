# REQ-005 — установка tree-sitter обесценивает мердж во всех JS/TS-карточках

**Тул:** `__HQ/tools/make_interface_card.py` (+ `show_pyfile_api` / `get_codeblock` как источник
объявлений)
**Нашлось:** 2026-08-27 в `hermes-filetools`, на карточке `desktop/plugin.js`.
**Цена ошибки:** молчаливая потеря всей прозы карточки при штатном re-stamp.
**Статус:** ЗАКРЫТО 2026-08-29, вместе с REQ-004 — см. `DONE__REQ-004+005_merge-identity-design.md`.
Диагноз уточнён по ходу: баг шире, чем «зависит от backend» — проявлялся и БЕЗ смены backend'а, на
любом JS/TS/C#/async-Python (имя вычислялось угадыванием по первому слову сигнатуры, а не по
позиции). Починено заменой угадывания на позиционный поиск + fuzzy-match на переименования.

## Что произошло

Карточка `__map/desktop/plugin.js.md` была заполнена, когда в интерпретаторе НЕ было
`tree-sitter-typescript` — объявления собирал регексп-бэкенд, и ключи записей выглядели так:

```
#### `function isOurTool(name)`
#### `const OUR_TOOLS = ['read_file', 'write_file', 'patch', 'search_files']`
```

Позже я поставила `tree-sitter` + `tree-sitter-typescript` (чтобы `get_codeblock --outline` работал
по `.js`). Следующий обычный re-stamp **без `--force`** выдал:

```
NEW → fill prose: isOurTool, coerceBody, isNoChange, brickTitles, buildBrick, ... (15 записей)
SALVAGED → removed from code, moved to '## Salvage': function, const
```

То есть мердж не узнал НИ ОДНОЙ записи: у tree-sitter-бэкенда ключи другой формы (без слова
`function`/`const`), поэтому все старые записи посчитались удалёнными, а все новые — новыми. Проза
уехала в `## Salvage`, карточка обнулилась. Восстановила `git checkout`.

**Это не `--force`** (REQ-004) — это дефолтный, «безопасный» путь. Пользователь не делал ничего
неправильного: он всего лишь доустановил зависимость другого тула.

## Почему это важнее, чем выглядит

1. **Срабатывает один раз и сразу на всё дерево.** `--all` после установки грамматики обнулит прозу
   во ВСЕХ `.js`/`.ts`/`.tsx` карточках проекта одним проходом.
2. **Причина и следствие разнесены по времени.** Грамматику ставят ради `get_codeblock`, а ломается
   `make_interface_card` — связь неочевидна, и легко списать на «тул сглючил».
3. **Обратное направление тоже верно:** карточки, заполненные С грамматикой, сломаются на машине
   БЕЗ неё (например в чужом контейнере). То есть формат карточки зависит от окружения, а карточки
   лежат в git и ездят между машинами.

## Что предлагаю

Минимум — **сделать сопоставление записей устойчивым к бэкенду**: нормализовать ключ перед
сравнением (снять ведущие `function`/`const`/`export`, оставить имя + список параметров). Имя
символа одно и то же в обоих бэкендах, различается только обёртка.

Дополнительно, дёшево и полезно: писать в карточку, каким бэкендом собраны факты
(`DECL_BACKEND: treesitter|regex` в невидимой строке или в шапке), и при re-stamp предупреждать,
если бэкенд сменился с прошлого раза — тогда пользователь увидит причину до, а не после.

Крайний вариант, если нормализация окажется дорогой: при нулевом совпадении записей на НЕПУСТОЙ
карточке — отказаться и попросить подтверждения. Ноль совпадений на заполненной карточке это почти
всегда ошибка, а не настоящая перепись файла с нуля.

## Чего НЕ надо делать

Не откатываться на регексп-бэкенд. Tree-sitter даёт точные границы блоков и внутреннюю карту
монофайла (`--outline` по `.js`), а на однофайловых плагинах это единственная замена карте связей.
Проблема в сопоставлении ключей, не в парсере.
