# REQ-010 — секция `## Runtime seams`: связь, которой нет в синтаксисе, но которая есть в работе

Тулы: `CARD_FORMAT.py` (формат), `make_interface_card.py` (штамп), `graph_from_cards.py` (граф),
`validate_cards.py` (проверка). Проект, на котором нашлось: hermes-filetools — питон-плагин с
JS-панелью и вторым питон-процессом (веб-сервер дашборда).

## Почему это не «хорошо бы», а «карта врёт»

`graph_from_cards.py` строит рёбра из импортов. Всё, что связывает модули **в рантайме**, для него
не существует. В нашем проекте таких связей три рода, и они несут основную нагрузку:

| связь | как выглядит в коде | что видит граф |
|---|---|---|
| загрузка ПО ПУТИ | `spec_from_file_location(path)` — путь собирается из `__file__` | ничего |
| HTTP между половинами | JS-панель зовёт `ctx.rest('/messages')`, маршрут в питоне | ничего |
| общий файл между процессами | агент пишет `<home>/filetools/…`, панель читает | ничего |

Из-за этого карта распадается на три несвязанных острова, о чём сам граф честно предупреждает
(«the map has 3 independent parts … their link is a runtime contract, not an import»), но сделать с
этим ничего не может.

**Цена уже уплачена, 2026-09-09.** В журнал добавился новый род записи. Его читают четыре места;
три из них граф знает по импортам, а четвёртое — `dashboard/plugin_api.py`, который грузит журнал
ПО ПУТИ. Спроси я тогда у графа «кого заденет новая форма записи», получил бы тринадцать имён и ни
одного намёка на четырнадцатое. Именно четырнадцатое и сломалось: 29 новых записей были прочитаны
как чтения, и вся панель ушла в серое на сессии, где всё было цело. В графе этот файл в тот момент
стоял на глубине 0 **без единого ребра** — идеально изолированный лист.

## Как воспроизвести на hermes-filetools и увидеть картину целиком

Всё ниже прогнано 2026-09-10, номера строк настоящие. Проект: `T:/AgentsWork/hermes-filetools`,
питон — их венв `y:/Hermess/hermes-agent/venv/Scripts/python.exe`.

**Шаг 1 — увидеть дыру.** Граф показывает файл без единого ребра:

```
python __HQ/tools/graph_from_cards.py --view depth --verbose 0 | grep -A 1 "dashboard/plugin_api"
```

Отдаёт `- **dashboard/plugin_api.py**` и следующий модуль — ни строки `→`, ни строки `←`.
Тот же файл в `--view tree` выглядит как отдельная группа `## dashboard/ (1)`, а в
`--discrepancies` это превращается в «the map has 3 independent parts».

**Шаг 2 — убедиться, что рёбра есть, просто они не импорты.**

```
grep -n "spec_from_file_location" dashboard/plugin_api.py
```

Шесть попаданий: строки **203, 231, 266, 1654, 1678** — по одной на каждый загружаемый наш модуль
(`_ledger`, `_msgindex`, `_tool_text`, `_select`, `_signal`), плюс строка 16 — объяснение в
докстринге, почему иначе нельзя.

**Шаг 3 — прочитать один загрузчик и понять механику.**

```
python __HQ/tools/get_codeblock.py --file dashboard/plugin_api.py --line 190
```

Отдаёт блок `_load_ledger()` (строки 190-213): имя модуля в `sys.modules`, поиск файла по
`_PLUGIN_ROOT / "file_ops" / "_ledger.py"`, `spec_from_file_location`, кеш. Путь СОБИРАЕТСЯ —
именно поэтому статический разбор его не увидит.

**Шаг 4 — посмотреть, сколько мест внутри файла на этом стоят.**

```
grep -n "_load_ledger()\|_load_msgindex()" dashboard/plugin_api.py
```

Девять вызовов `_load_ledger()` (808, 922, 986, 1050, 1088, 1167, 1342, 1398, 1604) и один
`_load_msgindex()` (1399). То есть одна невидимая графу связь несёт девять точек использования.

**Шаг 5 — то самое место, которое сломалось.**

```
python __HQ/tools/get_codeblock.py --file dashboard/plugin_api.py --line 986
```

Отдаёт `is_read_entry(entry)` (строки 970-989) — читателя, который до 2026-09-09 решал род записи
САМ («запись без поля `tool` — чтение по определению») и потому принял новый род за старый.
Рядом, для контраста, второй читатель того же журнала:

```
grep -rn "is_event" --include=*.py . | grep -v tests/
```

Девять попаданий в четырёх файлах: `file_ops/_ledger.py` (определение, 548), `_msgindex.py` (239),
`context_ctl/_stubs.py` (582, 687-695) и `dashboard/plugin_api.py` (987, 1171). **Первые три граф
знает по импортам, четвёртый — нет.** Вот это расхождение и есть предмет реквеста: три из четырёх
читателей найдёт любой инструмент, а четвёртого — только человек, который про него помнит.

**Шаг 6 — второй род шва, HTTP.**

```
grep -n "rest(" desktop/src/adapter.js
```

Строки 218, 261, 408 и далее — `ctx.rest('/reads?…')`, `/context-state`, `POST /context-focus`.
Каждая строка это ребро к маршруту в `dashboard/plugin_api.py`, и ни одно из них не выражено ничем,
кроме строкового литерала.

**Шаг 7 — третий род, общий файл между процессами.**

```
python __HQ/tools/get_codeblock.py --file context_ctl/_signal.py --line 1
```

Докстринг объясняет ситуацию прямым текстом: команда исполняется в процессе АГЕНТА, маршруты
панели — в веб-сервере дашборда, общее у них только файловое хозяйство. Связь реальна, выражена
совпадением путей в двух процессах, и в графе её нет.

**Итог воспроизведения:** три рода связи, ноль рёбер. Карта из 62 модулей показывает три острова,
хотя связный граф там один.

## Почему это НЕ ловится машинно (и не надо пытаться)

Рантайм-связь не выражена синтаксисом. `spec_from_file_location(Path(__file__).parent / name)` —
это вычисленный путь; строка `'/messages'` в JS — это не ссылка на питон-функцию; общий файл —
это вообще совпадение двух литералов в разных языках. Ни один разбор AST этого не увидит, а
эвристика по строкам даст ложные рёбра, которые хуже отсутствующих: ложное ребро выглядит как
знание.

Знает об этой связи ровно один субъект — тот, кто её написал. Значит инструмент должен не угадывать,
а **дать место, куда это записать**, и потом использовать записанное.

## Что предлагается

### 1. Новая необязательная секция карточки

```
## Runtime seams

- `file_ops/_ledger.py` — by-path — грузим через spec_from_file_location; форма записей общая
- `desktop/src/adapter.js` — http — зовёт наши маршруты через ctx.rest
- `<hermes home>/filetools/ctxctl/select/` — file — общий файл между процессами агента и панели
```

**Грамматика строки жёсткая, потому что её читает граф:**

```
- `<цель>` — <вид> — <зачем, свободным текстом>
```

- **цель** — путь к исходнику в проекте (тогда граф строит ребро) ИЛИ путь/URL вне проекта
  (тогда это просто заметка, ребра нет, но человек видит);
- **вид** — закрытый список: `by-path` · `http` · `file` · `event` · `process`. Закрытый именно
  затем, чтобы граф мог их различать в выводе и чтобы никто не выдумывал шестой;
- **зачем** — одна фраза. Без неё запись через полгода не отличить от мусора.

**Направление объявляется ОДИН раз, на зависимой стороне** — как и у импортов. Обратное ребро (`←`)
граф выводит сам; заставлять держать связь в двух карточках синхронно значит гарантированно получить
расхождение.

### 2. Штамп ставит секцию ПО ЗАПРОСУ

Флаг `--seams` у `make_interface_card.py`: добавляет пустую секцию с директивой
`<|Agent:NN перечисли рантайм-связи … |>`. Без флага секции нет вовсе — иначе она появится в
шестидесяти карточках, где её содержимое честно пусто, и превратится в шум (у нас уже есть ровно
такая беда, см. REQ-009: возвращающаяся директива обесценивает статус «awaiting agent»).

Раз секция заполнена — merge обязан хранить её как любую прозу. Это уже работает для `Doc links`,
механизм тот же.

### 3. Граф читает и рисует ПУНКТИРОМ

Отдельным видом ребра, не смешивая с импортами:

```
- **file_ops/_ledger.py**
  ← ×13 (…)                        ← импорты, как сейчас
  ⇠ by-path: dashboard/plugin_api.py   ← рантайм-шов
```

И тогда `--file file_ops/_ledger.py` наконец отвечает на настоящий рабочий вопрос: **кого заденет
изменение формы** — включая того, кто ломается молча.

Заметка про «3 independent parts» должна учитывать швы: острова, соединённые швами, островами уже
не являются, и предупреждение обязано это отражать — иначе оно приучает себя игнорировать.

### 4. Валидатор проверяет разрешимость цели

Цель-путь, которая не резолвится ни в карточку, ни в исходник, — это `unresolved`, ровно как у
зависимостей сейчас. Так секция не сгниёт: переименовали файл — валидатор скажет. Цель вне проекта
(URL, путь в hermes home) не проверяется, но и ребра не даёт.

## Чего делать НЕ надо

- **Не пытаться выводить швы автоматически** — см. выше; ложное ребро хуже отсутствующего.
- **Не делать секцию обязательной.** У большинства модулей рантайм-швов нет, и пустая секция в
  каждой карточке обесценит те три, где она несёт смысл.
- **Не требовать записи с обеих сторон.** Одна сторона плюс автоматическая инверсия.

## Что сделано пока, до появления секции

Швы записаны прозой в `Doc links` семи карточек (`plugin_api`, `_ledger`, `_msgindex`, `_select`,
`_signal`, `core.js`, `adapter.js`) с пометкой **RUNTIME SEAM** в начале строки. Человек их прочтёт,
граф — нет. Заводить нештатную секцию `## Runtime seams` руками не стал: валидатор считает
неканоническую секцию нарушением формата, и карточки стали бы невалидными. Когда секция появится в
`CARD_FORMAT.py`, эти строки надо перенести в неё — они уже в нужной форме, кроме вида связи.

## Честная оценка

Это работает ровно настолько, насколько секцию поддерживают в актуальном состоянии, — то есть
дисциплиной, а не проверкой. Но выбор не между «надёжно» и «по дисциплине», а между «по дисциплине»
и «никак»: сегодня этой информации нет вообще ни в каком виде, и каждый новый агент выясняет её
заново, ломая панель.
