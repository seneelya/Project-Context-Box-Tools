# REQ-004 + REQ-005 · устойчивая идентичность записи при merge карточек

**Статус:** ЗАКРЫТО, 2026-08-29. Патч в `make_interface_card.py` + регресс в `test_cardstamp.py`
(103/0), проверено живьём на `hermes-filetools/desktop/plugin.js` (24/28 записей сохранили прозу
на реальном re-stamp; 4 реально удалённых ушли в Salvage; 5 реально новых — на заполнение).
**Закрывает:** REQ-004 (`--force` тихо теряет прозу), REQ-005 (мердж теряет прозу при смене
backend'а) — обе оказались частным случаем одной и той же причины, чинятся одним патчем.

---

## 1. Реальный масштаб (проверено живьём, не гипотеза)

REQ-005 описывал баг как «ключи разной формы у разных backend'ов (tree-sitter/regex)». Проверка на
живом файле `hermes-filetools/desktop/plugin.js` (26 функций + 5 констант, все с прозой) показала,
что backend ни при чём: **обычный re-stamp тем же backend'ом, без единого изменения в коде**, стирает
прозу у ВСЕХ 26 функций разом:

```
[make_interface_card] merged plugin.js.md
  prose kept: 0 entries + summary, Dependencies External, How it works, Discrepancies
  NEW → fill prose: isOurTool, coerceBody, isNoChange, ... (30 записей)
  SALVAGED → removed from code, moved to '## Salvage': function, const
```

## 2. Причина

[`_entry_key`](../../../__HQ/tools/make_interface_card.py) вычисляет ключ записи, разрезая ТЕКСТ
готовой сигнатуры («первое слово»): `#### \`function isOurTool(name)\`` → берёт `function`.
Работает только тогда, когда сигнатура НЕ начинается со служебного слова языка — то есть только для
голого Python `def`. У JS/TS (`function`/`const`/`async`/`class`), C# (модификаторы+тип) и даже
Python `async def` первое слово — обёртка языка, не имя.

Хуже того: у ВСЕХ функций одного файла обёртка одинаковая (`function`), поэтому при разборе СТАРОЙ
карточки все 26 записей пишутся в `P["entries"]` под ОДНИМ ключом `"function"`, каждая следующая
затирает предыдущую — до сравнения с новым кодом доживает прозы одной (последней) функции. Остальные
25 гарантированно теряются, что бы ни делал дальнейший алгоритм сравнения.

## 3. Решение — три механики вместо угадывания по тексту

### 3.1 Словарь декораторов на язык
Маленькая таблица `keyword → есть/нет`, копируется под новый язык — тот же паттерн, что уже
существует у `_TS_BACKEND`/`_KIND_H3`. Пример для JS/TS:
`{"function", "async function", "const", "let", "var", "class", "export", ...}`; для Python —
`{"async"}` (голый `def` не имеет декоратора вообще). Язык файла уже известен на входе (`_lang(file)`).

Даёт не текст-угадывание, а точную ПОЗИЦИЮ имени в строке: «имя стоит сразу после одного из известных
декораторов этого языка (или в начале строки, если декоратора нет)».

### 3.2 Матчинг новых имён к старым записям (не наоборот)
Новое имя всегда известно точно — оно пришло от `ast`/tree-sitter/regex-парсера деклараций, не из
текста карточки. Поэтому ищем НЕ «извлеки имя из старой строки», а «есть ли это точное новое имя на
позиции имени в какой-то старой строке той же группы (`Functions`/`Constants`/`Classes`)»:

1. **Точное совпадение всей строки** (имя + сигнатура) → ничего не поменялось, прозу переносим как
   есть, без пометок.
2. **Имя совпало на позиции, сигнатура — нет** (например, функция стала `async`) → та же сущность,
   но не та же форма. Прозу переносим, спереди — маркер расхождения (см. 3.3).
3. **Точного имени нет ни в одной старой строке группы** → остаток старых записей и остаток новых
   имён матчим по похожести (нормализация регистра/подчёркиваний + процент совпадения символов);
   похоже — считаем переименованием, прозу переносим с маркером; непохоже — запись пропала → как
   сейчас, в `## Salvage`.

Поиск по группе (`Functions`/`Constants`/`Classes` отдельно) вместо всего файла нужен, чтобы имя,
случайно совпавшее с параметром ДРУГОЙ функции, не давало ложного совпадения.

### 3.3 Маркер расхождения — без счёта, без парсинга назад
Когда сигнатура/группа изменилась (случай 2 или 3), к тому, что уже лежит второй строкой после H4
(старая проза, какая бы она ни была), просто ПРИКЛЕИВАЕТСЯ маркер спереди — слепой конкатенацией,
без проверки «уже есть или нет»:

```
⚠ поменялась сигнатура - ⚠ поменялась сигнатура - Функция запускает пузырики.
```

Если карточку не открывали несколько re-stamp подряд, маркеры сами накапливаются друг перед другом —
это и есть индикатор «давно не смотрели», без отдельного счётчика. Пропадает стопка, когда
человек/агент реально переписывает прозу заново — переписывает и маркеры заодно (это часть той же
правки). Случай 3 (переименование по похожести) — свой, отдельный маркер/текст, чтобы отличать
«точно та же функция, просто другая форма» от «предположительно та же, имя другое — проверь».

## 4. REQ-004 (guard на `--force`) — встаёт поверх этого фикса

Guard «на карточке есть проза → `--force` без доп. флага падает» использует тот же
`_parse_old_prose`. Если считать «есть проза» ДО фикса 3.1–3.3, счётчик будет занижен на тех же
коллизиях (много записей схлопнулись в одну). Поэтому patch-порядок: **сначала 3.1–3.3, потом
guard** — тогда сообщение guard'а («карточка заполнена (N блоков прозы)») будет показывать реальное
число, а не число после коллизии.

## 5. Что НЕ делаем

- Не вводим отдельное поле/якорь с именем в формате карточки (рассматривали — избыточно: раз новое
  имя и так известно точно, достаточно ИСКАТЬ его в старом тексте по словарю декораторов, ничего
  дополнительно не храня).
- Не считаем номер расхождения числом — стопка маркеров текстом решает задачу дешевле.
- Не трогаем разбор Dependencies Internal / `_parse_why` — там ключ уже факт (`Import`), эта проблема
  их не касается.

## 6. Acceptance criteria

1. Re-stamp `hermes-filetools/desktop/plugin.js` без `--force` сохраняет прозу всех 26+5 записей
   (сейчас теряет все).
2. Функция, ставшая `async`, сохраняет прозу с маркером расхождения сигнатуры.
3. Переименованная функция (напр. `isOurTool` → `is_OurTool`) сохраняет прозу с маркером
   переименования, а не уходит в Salvage.
4. Функция, реально удалённая из кода, всё ещё уходит в Salvage (регресс не возникает).
5. `--force` на карточке с непустой прозой требует подтверждения/доп. флага; на пустом штампе работает
   как сейчас.
6. Регрессия зелёная: `test/check.py`, новые фикстуры на JS/TS/C#/async-Python в `test_cardstamp.py`.
