# REQ-020 — split_monster `--investigate`: ядро не уезжает; разбор большого класса изнутри

Найдено: слепой тест REQ-019 на Haiku (2026-11-17). Решение делать оба шага — владелица.
Исполнитель: Claude (Opus).

## Что было

Файл «три функции-помощника + dataclass + один большой класс, который пользуется ими всеми».
`--investigate` склеивает блоки в «семьи» по рёбрам «использует» — всё слилось в одну семью
(весь файл), и стартовая команда предложила унести весь файл в `inventory_Item.py`. Хаб (им
пользуются ≥ 3 блока) и оркестратор (использует ≥ 5) не сработали: каждым пользуется один блок,
класс использует четыре. Второе: 55 из 69 строк — класс, а `--investigate` видит только верхний
уровень; группы методов внутри (экспорт с общими `csv`/`io`/`json`) не видны.

## Что просим

1. **Ядро не уезжает.** В семье самый большой блок, который использует ≥ 2 других её блока и
   занимает не меньше, чем все остальные вместе, — ядро: остаётся в источнике. Его зависимости,
   которыми больше никто не пользуется («кормильцы»), предлагаются одной группой
   (`<stem>_<ядро>_deps`). Остальные блоки семьи пересчитываются в семьи без ядра.
2. **Большой класс — изнутри.** Если именованный блок-класс занимает больше половины именованных
   строк файла (и ≥ 20 строк), `--investigate` разбирает его методы (уровень 2 get_codeblock):
   размер, вызовы друг друга (имя метода среди идентификаторов), импорты источника и функции файла,
   которыми пользуются. Методы связываются вызовами, общим префиксом имени (`export_csv`,
   `export_json`) и импортами, которыми пользуется меньшинство методов. Группы выводятся фактами;
   группа без `__init__`/конструктора с «только они используют: …» — кандидат на второй проход
   (REQ-019): пример команды `--level 2 --into <класс в существующем файле>`.
   Языки: те, где есть имена (Python, JS/TS, C#, C/C++ через get_codeblock); C++-методы, определённые
   вне класса, и так верхнего уровня.
3. Факты + предложение, решение — агента. Ничего не пишет.
