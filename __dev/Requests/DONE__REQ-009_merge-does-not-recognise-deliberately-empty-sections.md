# REQ-009 — конфиг знает один язык · merge не считает «сознательно пустую» секцию заполненной

Тулы: `CONFIG__TOOLS.py`, `make_interface_card.py` (режим MERGE, он же `--all`),
`check_cards_freshness.py`. Проект, на котором нашлось: hermes-filetools, 62 карточки,
питон-бэкенд плюс JS-фронт.

## Почему проверяла

Массовый перештамп после большого куска работы: `--all` по питону и `--all --language typescript`
по фронту, чтобы подтянуть изменившиеся сигнатуры и списки потребителей. Это сработало ровно как
обещано — 47 карточек обновили факты, проза сохранилась, у изменившихся сигнатур появилась пометка
`⚠ поменялась сигнатура`. Претензий к основному сценарию нет.

Проблема вылезла на СЛЕДУЮЩЕМ шаге: после прогона валидатор показал 47 карточек в статусе
«awaiting agent», хотя большинство из них были доведены до конца незадолго до этого.

## Что нашла

**Merge не признаёт заполненными две секции, если их «заполнение» — это отсутствие содержания.**

| секция | что велит писать `Guide__MakeCard` | что делает merge |
|---|---|---|
| `## Discrepancies` | «else write `(none)`» | видит `(none)`, считает пустой, **возвращает директиву** |
| нота под `## Dependencies External` | «optional … else **DELETE** this line» | видит удалённую строку, **вставляет директиву заново** |

Проверено экспериментом на `__map/file_ops/_msgindex.py.md`:

1. в `Discrepancies` стоит `(none)` → перештамп → на его месте снова
   `<|Agent:02 docstring vs code contradictions; else write (none) |>`;
   stderr при этом честно перечисляет, что сохранил: `prose kept: 16 entries + summary,
   How it works, Doc links` — **`Discrepancies` в списке нет**;
2. в ту же секцию вписан обычный текст → перештамп → текст **на месте**, и stderr теперь говорит
   `prose kept: … Doc links, Discrepancies`.

То есть механизм рабочий, вопрос только в трактовке «пусто». Ровно то же с нотой про внешние
импорты: её собственная инструкция велит строку УДАЛИТЬ, а merge читает отсутствие строки как
«агент ещё не дошёл» и печатает директиву снова.

**Масштаб на живом проекте:** после одного массового прогона директива про внешние импорты
вернулась в **27 карточек** из 62 (посчитано скриптом-уборщиком, который её вычистил). Карточка,
доведённая до конца, не может остаться доведённой: любой следующий `--all` откатывает её в
«awaiting agent», и статус перестаёт что-либо значить — а он единственный способ узнать, где
проза действительно не написана.

## Как воспроизвести на hermes-filetools

Прогнано 2026-09-10. Питон — их венв `y:/Hermess/hermes-agent/venv/Scripts/python.exe`,
запуск из корня проекта.

**Находка 1 — «сознательно пустая» секция не считается заполненной.** Двумя перештампами одной
карточки, ничего не меняя в исходнике:

```
grep -n "Discrepancies" -A 2 __map/file_ops/_msgindex.py.md      # видим (none)
python __HQ/tools/make_interface_card.py file_ops/_msgindex.py --project-root . --out __map/file_ops/_msgindex.py.md
grep -n "Discrepancies" -A 2 __map/file_ops/_msgindex.py.md      # на месте (none) снова директива
```

stderr второй команды перечисляет сохранённое: `prose kept: 16 entries + summary, How it works,
Doc links` — `Discrepancies` в списке НЕТ. Контрольный опыт, показывающий, что механизм исправен:
впишите в ту же секцию любой обычный текст, перештампуйте — текст на месте, и stderr теперь говорит
`prose kept: … Doc links, Discrepancies`. Значит дело именно в трактовке `(none)` как пустоты.

То же самое с нотой под `## Dependencies External`: удалите строку-директиву (её собственная
инструкция велит «else DELETE this line»), перештампуйте — она вернётся.

Масштаб на всём проекте меряется так:

```
python __HQ/tools/validate_cards.py --project-root . | tail -1
```

До массового прогона было `62 clean, 4 awaiting agent`, сразу после `--all` стало
`62 clean, 47 awaiting agent`, из них 27 — только из-за вернувшейся ноты про внешние импорты.

**Находка 2 — конфиг знает один язык.** Полный обход требует двух команд, и первая молчит о том,
что покрыла половину:

```
python __HQ/tools/make_interface_card.py --all --project-root .
# [make_interface_card] --all: languages=['python'] exts=['.py']
# [make_interface_card] --all: 41 files -> 5 new, 36 merged, 0 forced, 0 blocked, 0 errors

python __HQ/tools/make_interface_card.py --all --language typescript --project-root .
# [make_interface_card] --all: languages=['typescript'] exts=['.js', '.jsx', '.ts', '.tsx']
# [make_interface_card] --all: 21 files -> 0 new, 21 merged, 0 forced, 0 blocked, 0 errors
```

Первый вывод выглядит как полный обход проекта; на деле 21 файл фронта не тронут.

Слепота свежести проверяется так:

```
python __HQ/tools/check_cards_freshness.py | head -2
git log -1 --format="%h %ad" --date=iso -- desktop/src/core.js
stat -c '%y' __map/desktop/src/core.js.md
```

Отчёт свежести не упоминает ни одного `.js` (в нём только `.py.md`), а сравнение дат показывает
реальное отставание карточки от кода — у меня было двое суток при зелёном отчёте.

Где смотреть в самих тулах:

```
grep -n "LANGUAGE" __HQ/tools/CONFIG__TOOLS.py            # одиночная строка, не список
grep -n "py.md\|\.py" __HQ/tools/check_cards_freshness.py | head
```

## Вторая находка, и она корневая: КОНФИГ ЗНАЕТ ТОЛЬКО ОДИН ЯЗЫК

`CONFIG__TOOLS.LANGUAGE` — одиночная строка (`LANGUAGE = "python"`). Проект с бэкендом на питоне и
фронтом на JS у неё не выражается, и это протекает наружу как минимум в двух местах.

**1. `make_interface_card.py --all` покрывает половину проекта.** Полный обход требует ДВУХ
прогонов, второй — руками с флагом:

```
make_interface_card.py --all --project-root .                        # 41 файл (.py)
make_interface_card.py --all --language typescript --project-root .  # 21 файл (.js)
```

Забыть второй легко, и ничто об этом не скажет: первый прогон отчитается «41 files -> …, 0 errors»,
и выглядит это как полный обход проекта.

**2. `check_cards_freshness.py` считает свежесть ТОЛЬКО `.py.md`** (так и написано в его `--help`:
«Freshness of .py.md cards»). То есть JS-карточки устаревают НЕВИДИМО. Живой пример: у меня
`desktop/src/core.js.md` отставал от кода на двое суток, а отчёт свежести был зелёным — «total=30
fresh=17 outdated=13», и ни одной джаваскриптовой строки в списке. Зелёный отчёт при этом читается
как «карта актуальна вся».

**Что нужно:** дать конфигу зарегистрировать НЕСКОЛЬКО главных языков проекта — список вместо
строки, например

```python
LANGUAGES = ["python", "typescript"]   # LANGUAGE оставить синонимом первого, для совместимости
```

— и научить оба тула читать его: `--all` без флага обходит все зарегистрированные языки,
`check_cards_freshness` считает свежесть по всем их расширениям. Тогда «полный обход» и «зелёная
свежесть» начнут означать то, что читаются.

Флаг `--language` при этом остаётся и продолжает значить «только этот язык» — он полезен, когда
надо перештамповать одну половину.

## Что, скорее всего, нужно сделать — по обеим находкам

1. **Дать конфигу список языков** (см. выше): `--all` без флага обходит все зарегистрированные,
   `check_cards_freshness` считает свежесть по всем их расширениям. Это корневая правка: она
   закрывает и «половину проекта не обошли», и «зелёная свежесть врёт».
2. **Считать секцию заполненной, если агент её ЯВНО закрыл.** Два кандидата, оба дешёвые:
   - трактовать `(none)` (и `(нет)`) в `Discrepancies` как заполнение — это буквально то слово,
     которое велит писать гайд;
   - для необязательной ноты — не возвращать директиву, если секция `Dependencies External` уже
     существует и содержит список импортов: значит по ней проходили.

Обходной путь, которым воспользовалась сейчас: два прогона `--all` руками плюс скрипт, вычищающий
возвращённую директиву по всем карточкам. Работает, но это ровно та ручная работа, ради устранения
которой массовый штамп и существует.

**Чего трогать НЕ надо.** Накопление пометок `⚠ поменялась сигнатура` (две подряд на одной записи
после двух перештампов) — не дефект, а решение владельца инструмента: пометки просто дописываются,
«ЛЛМ при прочтении разберётся». Проверяла как раз на этом и ошиблась в первой редакции реквеста —
записываю, чтобы следующий не пошёл чинить то же самое.
