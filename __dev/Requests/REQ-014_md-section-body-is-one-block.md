# REQ-014 — `.md`: тело раздела — один блок `~content`, внутри него лесенка слепая

## Зачем это нужно (контекст извне)

hermes-filetools (`Plan30`, 2026-10-07) читает файлы через вендорную копию `get_codeblock`:
обычный `read_file --line N --count N` выравнивает оба края куска по блокам
(`views.block_range`: край уходит к самому внешнему блоку в пределах `tol = count // 2`). Для
кода это работает: функции, `if`, `try` — блоки. Для markdown — почти нет: внутри раздела нет
ни одного блока мельче всего его тела, поэтому конец куска в длинном разделе почти всегда
режется посреди текста с пометкой `| cut inside block 10-71 |`, а начало не встаёт на абзац.

## Что нашла (поведение сейчас)

`__HQ/plans/Plan30__read-by-blocks.md` проекта hermes-filetools, строка 20 — середина пункта
списка в разделе «Вижен» (строки 9–71):

```
get_codeblock.py --file Plan30__read-by-blocks.md --line 20
  1 |  1-249| Plan30 — …
  2 |   9-71|   Вижен — что видит модель
  3 |  10-71|     ~content
  → |   → 20|     выключается настройкой …
```

`--line 20 --outline` — `.3 [10-71] ~content` и больше ничего. Лесенка кончается на теле
раздела: пункты списка, абзацы, fenced-код, цитаты, таблицы внутри раздела блоками не являются.

`block_range(src, 18, 6)` (просили 18–23, `tol 3`) → начало 18, конец 23 с `cut [10, 71]`:
выровнять не к чему.

Для `.txt` то же правило уже есть и работает: абзацы, разделённые пустой строкой, — блоки
(`reader/backends/plaintext.py`).

## Чего хочется

Внутри тела раздела `.md` — блоки следующего уровня, тот же принцип, что у `.txt`:
- **абзац** (строки до пустой);
- **пункт списка верхнего уровня** с его продолжениями и вложенными пунктами (`- …`, `1. …`);
- **fenced-код** (```` ``` ```` / `~~~`) — один блок целиком, внутрь не заходить;
- **таблица** (подряд идущие строки `|…|`) и **цитата** (`> …`) — по блоку.

Это блоки-заполнители (`.` в оглавлении, без имени): в оглавлении на уровне файла их не видно
(как сейчас не видно `~content`), они нужны лесенке, `--line N --outline` и `block_range`.
Инварианты 6/7/9 `reader/CONTRACT.md` — те же: один `[start-end]` на блок для карты и адресации,
возвращённая ступень содержит строку.

## Как проверить

- `get_codeblock --line 20` на файле выше даёт ступень `4 | 19-20 | - **…` (пункт списка)
  под `~content`.
- `views.block_range` на длинном разделе ставит конец на конец пункта/абзаца, `cut` — `None`.
- Оглавление файла (`--outline`) не меняется побайтно: блоки тела — заполнители.
- Golden `test/check.py` — новые случаи в `test/mdSRC/` (список с продолжениями, код внутри
  пункта, таблица, цитата).
