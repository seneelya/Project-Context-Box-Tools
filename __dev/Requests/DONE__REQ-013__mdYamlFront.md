# REQ-013 — `get_codeblock` не видит YAML frontmatter в `.md`: паспорт документа тонет в `~content`

## Зачем это нужно (контекст извне)

В игровом GDD-репо (`dVOrbitals/dvOrbital__GDD`) договорились, что у предметных
markdown-документов появляется **YAML frontmatter** — «паспорт» файла: `code`
(идентификатор системы: `sa`, `mc`, `dc`…), `version`, `updated`, `aliases`, иногда
`status`. Это SSoT для агентской работы: увидев паспорт первым в файле, ИИ-агент знает
версию и код документа, не заходя внутрь. Проблема — **пока frontmatter не задан как
первый уровень структуры markdown**, инструмент его просто не показывает.

## Что нашла (поведение сейчас)

Файл с frontmatter:

```markdown
---
aliases:
  - радиометрический вид
code: vis
version: 1.0.0
---

# Заголовок раздела

Текст…
```

прогон `get_codeblock.py --file <этот.md>` (без аргументов = `--outline`) отдаёт:

```
<!-- outline — max depth 1, showing levels 1..1 -->
<!-- . [1-11] ~content -->
```

Весь YAML (строки 1–5) + заголовок + текст склеились в **один анонимный filler-блок**
`~content`. Паспорт не выделяется, по нему нельзя адресоваться (`--line 3 --query` даст
кусок прозы, а не структурированный frontmatter), и `aliases`/`code`/`version` как
поля инструмента не видны.

## Корень (where)

Живой путь `.md`-аутлайна идёт через ридер, а не через старый хендлер:

- `get_codeblock/reader/backends/markdown.py::MarkdownBackend.root()` строит дерево из
  `_headings(lines)` + `_section_end(...)` (импортирует их из
  `handlers.markdown_handler`, чтобы не дублировать).
- `handlers/markdown_handler.py::_headings()` — единственный источник «что является
  заголовком». Он матчит только ATX (`^(#{1,6})\s+…`) и пропускает fenced-код
  (``` / ~~~). Строки `---` в frontmatter **не** являются fence'ами (fence требует
  backtick/tild), значит YAML-блок не распознаётся как граница — он просто остаётся
  «текстом до первого заголовка».
- В `_build()` (`reader/backends/markdown.py`) строки `[0, первый_заголовок)` оборачиваются
  в один узел `MdNode('content', …)` → в аутлайне это и есть полоса `~content`.

Вывод: чтобы frontmatter стал видимым и адресным уровнем, его надо **распознать как
отдельный блок** на уровне парсинга заголовков — там, откуда он берётся (`_headings`), а не
заплаткой в рендере (иначе разойдутся map и `--line`, нарушение инварианта #6 «один вопрос —
один ответ»).

## Что нужно сделать

**1. Распознать frontmatter как первый узел документа.** В `handlers/markdown_handler.py`
(единый источник) добавить детекцию: если строка 0 файла == `---`, ищется закрывающая
строка `---` (или `...`) — интервал `[0, close]` = frontmatter. Вернуть его в `_headings()`
(или соседней функции) как особый «псевдозаголовок» уровня 0 с меткой, напр. `meta`.

**2. Дать ему роль landmark, а не filler.** В `MarkdownSpec.role()` (`reader/backends/markdown.py`)
узел frontmatter → `'landmark'` (как заголовки), чтобы он появился в `--outline` как
отдельная строка уровня 0 с подписью `[meta]`, и чтобы `--line N --query` внутри него
возвращал сам YAML-блок целиком.

**3. Показать ключи в подписи.** Подпись блока — не просто `meta`, а список ключей
(топ-уровень): `[meta: code, version, updated]`. Это и есть «паспорт первым делом» для агента.
Парсинг значений НЕ обязателен (не тащить YAML-парсер в ноль-dep путь .md) — достаточно
вытащить имена ключей строками `^\w[\w-]*:`. Если захотим значения — это уже опционально, через
существующий `yaml_backend` (tree-sitter-yaml), но не по умолчанию.

**4. Не ломать инварианты.** Файл БЕЗ frontmatter ведёт себя как сейчас (ни одного нового
узла). Frontmatter никогда не считается заголовком для целей `_section_end`/иерархии (он не
владеет секциями ниже, он — самодостаточный блок перед первым H1). `--line N` на строке внутри
frontmatter → адресует `[meta]`, а не `<file>`.

## Приёмка (как проверить)

- Файл c frontmatter: `get_codeblock.py --file X.md` в аутлайне показывает первую строку
  уровня 0 `[1-K] [meta: code, version, …]`, ниже — обычные заголовки со своими номерами.
- `--line <строка внутри frontmatter> --query` возвращает весь YAML-блок (от `---` до `---`).
- Файл без frontmatter: аутлайн идентичен текущему (регресс 0).
- Золото: добавить в тесты кейс .md с frontmatter и зафиксировать аутлайн + query (как сейчас
  фиксируются markdown-кейсы в `test/check.py`).

## Примечание по приоритету/объёму

Это фича, не баг — ничего не сломано, просто информация «спрятана». Маленький самодостаточный
срез (1 источник `_headings` + 1 роль в Spec). Связан с темой: дообучить `get_codeblock` на
YAML frontmatter (см. обсуждение дизайна GDD-документации, где frontmatter выбран как паспорт
файла и SSoT версии/кода системы).
