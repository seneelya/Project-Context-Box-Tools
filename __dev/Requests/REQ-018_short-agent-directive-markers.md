# REQ-018 — короткие маркеры директив в карточках: меньше лишних токенов при заполнении

Найдено: Opus (dVOrbitals `sim`, 2026-11-15), при заполнении карточек пачками (Task66, Haiku). Идея маркера — владелец.

## Что видно (sim, 652 карточки, 276 ждут агента)

1 497 директив `<|Agent:NN … |>`. По тексту:

| Директива | Сколько | Длина текста |
|---|---|---|
| `why?` (у каждого import) | 548 (37 %) | короткая |
| `docstring vs code contradictions; else write (none)` | 229 | ~50 симв. |
| `replace with a concise one-line summary — what this file is and does` | 226 | ~70 |
| `describe the actual mechanism/flow after reading the source; keep it precise — do NOT generalize a per-case detail to "each/every" unless it holds for all` | 222 | ~150 |
| `one line ONLY if a lib above is non-obvious; else write (none) (do NOT edit the import list)` | 152 | ~90 |
| `what this family is for — one line` | 100 | ~35 |
| `write short does+role, or remove` | 20 | ~30 |

Длинный текст правила повторяется в каждой карточке: исполнитель читает его сотни раз, хотя правило одно и живёт в гайде. Пачка из 25 карточек (81 директива) стоила Haiku ~127 тыс. токенов. Рендер-пачки по 140–160 директив стоят примерно вдвое больше.

## Что просим

1. **Короткий маркер** вместо фразы. Номер плюс короткий ключ рода: `<#45 why>`, `<#46 mech>`, `<#47 sum>`, `<#48 fam>`, `<#49 contra>`, `<#50 ext>`, `<#51 role>`. Голый номер `<#45: >`, как предложил владелец, ещё короче, но тогда исполнителю на каждый маркер нужна легенда. Ключ в 3–6 символов снимает и это и почти ничего не стоит.
2. **Легенда — одна.** Полный текст каждого рода лежит в `Guide__MakeCard.md` (Step 3) и в docstring `CARD_FORMAT.py`, а не в карточке. В карточке не больше одной строки сверху вида `Fill <#NN key> markers — Guide__MakeCard.md Step 3`, а лучше ни одной: гайд исполнитель и так читает.
3. **`why?` у каждого import → одна директива на весь блок импортов** (`<#NN why>`: «одна строка на импорт, только где связь неочевидна из колонки Symbols, иначе удалить строку»). Либо штамп сам заполняет «why» именами символов, если колонка Symbols не пуста. Это 37 % работы.
4. **`ext` — только если внешние библиотеки есть.** Нет внешних импортов — штамп сам пишет `(none)`.
5. **Совместимость.** Детекторы (`_AGENT_RE`, `is_agent`, `validate_cards.py` «awaiting agent», мерж при повторном стампе) понимают и новую форму, и `<|Agent:NN …|>`, и легаси `<Agent:…>`. Повторный стамп переводит старые директивы в короткую форму, заполненную прозу не трогает. Нумерация `number_directives` та же.

## Проверка

- На `sim`: повторный стамп 276 карточек — те же места директив, только короче. `validate_cards.py` считает те же 276 «awaiting agent». Заполненные карточки (`pack00`, `73ae7cee`) не меняются.
- Счёт токенов одной пачки до и после (например `pack02` sim, `src/probe/gfx`).
- Тесты инструментов `__dev` зелёные.

## Решение — 2026-11-15, владелец + Opus

Та же идея уже лежала в `plans/Plan06__short-agent-markers.md` (2026-09-17). Делается по этому реквесту, Plan06 закрывается им.

**Маркер `<|fillN|>`** (`<|fill5|>`, номер без ведущего нуля). Замер на токенайзерах Qwen3.6 и Gemma-4 (`c:\RAM_Cache\Temp\req018\tok*.py`):

| Маркер | Токенов |
|---|---|
| `<\|Agent:05 why? \|>` (самый короткий сегодня) | 6–10 |
| `<\|fill5\|>` | 4 |
| `{{5}}` / `[[5]]` | 2–4 |

- Цифры режутся по одной, `05` = 2 токена, поэтому без ведущего нуля.
- Голые `{{N}}` / `[[N]]` отвергнуты: `{{` бывает в C++/f-строках/Jinja, `[[` — атрибуты C++ и вики-ссылки. Детекторы (`validate_cards` «awaiting agent», `graph_from_cards`, мерж) спутали бы их с кодом в сигнатурах и seam hints. `<|` оставлен, потому что его нет ни в коде, ни в markdown (`CARD_FORMAT.py`, описание маркера).
- Слово `fill` — +1 токен, зато маркер читается как действие и уникален.
- Закрывающая `|>` делает `fill5` не префиксом `fill50`, трюк с пробелом больше не нужен.

**Вид директивы задаёт её место в карточке, а не текст маркера.** Под «How it works» — механизм, в строке семейства — назначение, под H1 — summary и т. д.

**Шапка — одна строка-ссылка на гайд, HTML-комментарием над H1** (`<!-- Fill each <|fillN|> by its place: __HQ/guides/Guide__MakeCard.md Step 3 -->`). Сначала в шапке был полный список «что писать где» (~156 токенов): на sim карточки от этого стали на 12–16 % тяжелее, чем со старыми маркерами. Список перенесён в гайд, шапка только ссылается. Все читатели (`validate_cards`, `graph_from_cards`, `collect_card_bundle`, мерж штампа) ищут H1 как первую строку `# ` и всё выше пропускают, так что сводка «первая непустая строка после H1» не ломается. Шапка ставится, только пока в карточке есть хоть один `<|fillN|>`; перештамп заполненной карточки её убирает. Полный текст правил — в `Guide__MakeCard.md` Step 3.

**Перештамп переводит старые директивы в новую форму и не теряет прозу.** Мерж и сейчас считает слот с директивой пустым (`_is_ph` → `is_agent_directive`) и ставит туда свежую директиву от `cf.agent()`. Детекторы узнают все три формы (`<Agent:…>`, `<|Agent:NN …|>`, `<|fillN|>`), `number_directives` переписывает любую найденную директиву в `<|fillN|>`.

**Формат карточки 1.3.0 → 1.4.0.**

**Пункты 3–4 реквеста.** 4 уже выполняется: нет внешних импортов — штамп пишет `(none)` без директивы. 3 (`why?` у каждого импорта) в этот проход не входит, решается отдельно.

## Результат — 2026-11-15, Opus

- `CARD_FORMAT.py`: `agent()` → `<|fill|>`, `number_directives` нумерует `<|fillN|>` и переписывает в него старые формы; детекторы узнают все три формы; `FILL_HEADER` / `is_fill_header`; формат 1.4.0.
- `make_interface_card.py`: все слоты — один маркер; шапка над H1, пока есть незаполненный слот; мерж выбрасывает старую шапку, как строку версии.
- Документы: `Guide__MakeCard.md` Step 3 — что писать в каждом месте; `Guide__AuditCards.md`, TLDR, README, `TOOLS.md`, сообщения `validate_cards`.
