# REQ-022 — GLSL: глобальная переменная с инициализатором в скобках теряет ключ при перештамповке

## Что видно

Живой проект, 18 Nov 2026, карточка шейдера `batch_approach.glsl` (формат 1.5.0, штамп после REQ-021). Агент заполнил
прозу и перештамповал карточку; две записи не нашли своего места:

```
NEW — fill prose: g_fr_rel, g_ap_have
SALVAGED — removed from code, moved to '## Salvage': dvec3, bool
```

Записи:

```
#### `dvec3 g_fr_rel = dvec3(0)`
#### `bool g_ap_have[3] = bool[3](false, false, false)`
```

Проза ушла в `## Salvage` под ключами `dvec3` и `bool`, а у записей снова `<|fillN|>`. Соседние глобальные переменные с
инициализатором без скобок (`uint g_ap_mode = 0u`, `double g_ap_h = 1.0LF`, `bool g_fr_open = false`) сливаются
нормально. Похоже, ключ записи при разборе старой карточки берётся неверно, когда в инициализаторе есть `(...)`: имя
теряется, остаётся тип.

Обход в проекте: проза вписана руками, `## Salvage` удалён. При следующей
перештамповке ошибка повторится.

## Что просим

Ключ записи глобальной переменной GLSL — её имя, при любом инициализаторе (вызов конструктора, массив
`T[N](...)`, вложенные скобки). Проверить и другие формы: `const dvec3 X = dvec3(...)`, `shared`-массивы.

## Проверка

Фикстура `batch_approach.glsl` — её нет в приватном наборе, при надобности скопировать из проекта в `test/secret/`. Синтетика для коммитящихся тестов: глобальные `dvec3 a = dvec3(0);` и
`bool b[3] = bool[3](false, false, false);` с прозой; перештамповка — `prose kept` для обеих, без `## Salvage`.

## Результат — 2026-11-18, Opus

- Причина: `stamp_langs/glsl.py` `entry_key` искал `(` раньше `=`, и у `dvec3 a = dvec3(0)` ключом становилось
  слово перед скобкой инициализатора (тип). Теперь `=` до первой `(` → имя берётся слева от `=` (без `[N]`).
  Функции, блоки, `layout(...)`, спец-константы — как были.
- Формы проверены: конструктор, массив `T[N](...)`, `const` с вложенными скобками, `shared`-массив, спец-константа.
- test_glsl_stamp 66/0 (+6): ключи и перештамповка синтетики — проза цела, без `## Salvage` и новых fill.
  Без правки тест ловит 5 провалов.
- Живая карточка `batch_approach.glsl` перештампована в памяти (без записи): Salvage нет, fill нет, проза
  `g_fr_rel`, `g_ap_have` на месте. В проект ещё не задеплоено.
