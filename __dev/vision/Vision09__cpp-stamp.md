> `Vision02__cards-layer.md`; пути/штаб — `Vision08__hq-as-anchor.md`. Номер сквозной с

## 1. Проблема

Штемпель (`make_interface_card`) и связи (`find_code_usage`) умеют Python / TS-JS / C#. Первый
C/C++-проект — форк llama.cpp (`y:\SRC\llama.cpp_mix`, цель — сборка CUDA+Vulkan и микс-вычисления).
`get_codeblock` C++ уже читает (tree-sitter `tree_sitter_cpp` установлен), штемпель — нет.

Страх владельца (обоснованный): C/C++ — это `#ifdef`. Связь может существовать или нет в зависимости
от одного флага сборки; карточка, которая этого не видит, врёт. Нужно **обобщённое** решение (любой
C/C++-проект), а не ручной разбор llama.cpp.

## 2. Главная идея: условия ПОМЕЧАЕМ, а не разрешаем

Tree-sitter разбирает `#if/#ifdef/#ifndef/#elif/#else` как узлы дерева (`preproc_ifdef`,
`preproc_if`, …). Значит, для каждого объявления и каждого `#include` штемпель МЕХАНИЧЕСКИ знает, под
каким условием он стоит, — и записывает это как факт:

```
#include "ggml-cuda.h"   [if GGML_USE_CUDA]
```

Шов «пропадает от одного ifdef» превращается в **условное ребро** — записанный факт «есть только при
флаге X». Это ровно compile-not-retrieve: подготовленный ориентир, а не догадка.

Проверено на живом дереве (2026-09-30): в llama.cpp условная компиляция бэкендов СОБРАНА в одном месте
— `ggml/src/ggml-backend-reg.cpp` (`#ifdef GGML_USE_CUDA` → `register_backend(ggml_backend_cuda_reg())`,
так же Vulkan и ещё ~15). Ад локализован, не размазан.

## 3. Что штемпель извлекает сам (без сборки)

1. **Public API — из заголовков** (`.h .hpp .hh .hxx .cuh`): функции, структуры/классы, enum,
   typedef/using, публичные `#define`. Экспортные макросы (`GGML_API`, `GGML_CALL`, `LLAMA_API` …)
   сбивают парсер → их список в конфиге (`CPP_STRIP_MACROS`), штемпель вырезает их перед разбором.
2. **Рёбра — из `#include "..."`**. Резолв: папка файла → `CPP_INCLUDE_DIRS` из конфига (для llama.cpp:
   `include`, `ggml/include`, `src`, `common`, `ggml/src`). `<...>` — внешняя зависимость. Каждое
   ребро несёт своё условие (колонка/пометка в таблице зависимостей).
3. **Пара «заголовок ↔ реализация»** — ребро `implements`: по одинаковому стему (та же папка →
   поиск по дереву), спорные пары — `CPP_PAIRS` в конфиге. Карточка реализации (`.c .cpp .cc .cu`)
   тонкая: «реализует `x.h`» + внутреннее (`static`, анонимный namespace) + зависимости; API из
   заголовка НЕ дублирует.
4. **Условные зоны файла** — список флагов, от которых зависит файл («целиком под `GGML_USE_VULKAN`»,
   «3 блока под `GGML_USE_CUDA`»).
5. **Подсказки швов** (grep-детектор, как `seam_scanner` сейчас): структуры из указателей на функции
   и их заполнение (`.compute = ggml_backend_cuda_compute`), `dlopen`/`LoadLibrary`/`GetProcAddress`,
   вызовы регистрации. Штемпель только ПОМЕЧАЕТ строки; что это за шов и зачем — пишет автор прозы.

## 4. Опционально — правда НАШЕЙ сборки

Есть `compile_commands.json` (CMake `-DCMAKE_EXPORT_COMPILE_COMMANDS=ON`, генератор Ninja — VS-генератор
его не пишет) → штемпель берёт `-D` и include-пути КАЖДОГО файла и вычисляет простые условия
(`defined(X)`, `!`, `&&`, `||`, `X` как 0/1). Ребро получает `live` / `dead` для этой сборки;
сложное выражение — честное `unknown`, не угадываем. Нет файла → граф показывает все варианты с
метками условий (тоже полезно: видно, что флагами включается).

## 5. Граф

Узлы — файлы. Рёбра: `include` (+условие), `implements`, швы (`Runtime seams`). Фильтр
`--flags GGML_USE_CUDA,GGML_USE_VULKAN` — граф конкретной сборки. Обратные include («кто включает
заголовок») на первое время заменяют `find_code_usage` для C++.

## 6. Зона: где ДЕЛАЕМ карточки ≠ куда ВИДНЫ связи

Весь llama.cpp (~3600 файлов) картировать бессмысленно — нужна зона. Но связь может ехать из одной
папки в совсем другую (замечание владельца), поэтому зона ограничивает ТОЛЬКО штемпелевание:

- **зона** — `--all --path <поддерево>` (или `STAMP_DIRS` в конфиге): карточки только здесь;
- **прямые рёбра** (из зоны наружу) резолвятся по ВСЕМУ `PROJECT_ROOT` — ребро на файл вне зоны
  записывается как есть (исходник без карточки → валидатор показывает его «pending», связь не теряется);
- **обратные рёбра** (кто СНАРУЖИ использует зону) — дешёвый построчный скан ВСЕГО дерева на
  `#include` и паттерны швов (секунды даже на 3600 файлов) → в карточку «кем включается / кто
  регистрирует, вне зоны».

## 7. Где система честно сдаётся — и обязана это сказать

Код, порождённый макросами (X-macros, `##`-склейка), тяжёлые шаблоны, `#ifdef` посреди выражения →
штемпель помечает **«непрозрачная зона — читать код»**. Честное «не знаю» лучше уверенной лжи в карточке.

## 8. Разделение труда

**Штемпель — факты** (п.3–6) · **Grok — проза** (смысл, владение памятью, потоки, классификация швов)
· **`validate_cards` — формат**. Сильная модель (Claude) — вижен/план/приёмка.

Формат карточки остаётся тем же (`CARD_FORMAT.py`); прибавляется: условие у ребра зависимости и,
вероятно, новые `Kind` в словаре швов — `build-flag` (условное ребро), `vtable` (вызов через таблицу
функций), `registry`, `dlopen`. Точный вид — в плане, с бампом `CARD_FORMAT.VERSION`.
