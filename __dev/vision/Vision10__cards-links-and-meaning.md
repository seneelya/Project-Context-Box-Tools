## 1. Проблема (цифры приёмки 2026-09-30)

На мега-API карточка перестала быть ориентиром:

| | `ggml/include/ggml.h` | его карточка (Plan08) |
|---|---|---|
| строк / байт | 3022 / 119 КБ | 2637 / **144 КБ** (до свёртки потребителей — 8486 строк) |
| документация автора | 633 строки комментариев | потеряна |
| проза | — | 457 пустых мест |

- Карточка **дублирует** 454 сигнатуры — хуже оригинала (без комментариев автора). Оглавление
  самого `.h` и так даёт `get_codeblock --outline`.
- Ценное в ней — только то, чего в файле НЕТ: кто использует что (по папкам), кто включает файл
  во всём дереве, пара с реализацией, условия сборки.
- Граф видит только файлы С карточками: при зоне в 37 файлов `used-by` врёт о размере мира.
- Сканы (include, потребители) каждый раз заново: 4 с на include всего дерева, 31 с на поиск
  потребителей для 36 карточек. На проекте крупнее — минуты.

Замысел карточек изначально списан с заголовков C/C++ (владелец). Значит, у C/C++-заголовка
карточка не должна его повторять — она ссылается на него и добавляет то, чего в нём нет.

## 2. Три слоя, у каждого своя работа

1. **Карточка — связи и смысл** (compile-not-retrieve). Что это за файл и зачем; внешние связи
   (таблица зависимостей, кто использует, кто включает, условия); место для «нафига» — проза.
   НЕ копия API там, где исходник сам интерфейс.
2. **Граф — топология файлов.** Рёбра из карточек И из исходников: файл без карточки — тоже узел
   (помечен «без карточки»), его рёбра известны из скана. Граф честен при любой зоне.
3. **Запросы — по требованию** (retrieve): «кто вызывает X», «цепочка от A до B». Сейчас —
   `find_code_usage --symbol` (grep-точность). Позже — clangd по `compile_commands.json` (ссылки,
   иерархия вызовов с учётом макросов и флагов; Plan08 шаг 9 становится ключом к этому слою).
   Свой семантический индекс C++ НЕ строим.

Порядок работы агента: карточка (где я, что это) → граф (куда ведёт) → запрос (точная цепочка)
→ `get_codeblock` (код, с комментариями автора).

## 3. Карточка C/C++-заголовка: «API — в исходнике»

```markdown
## Public API

API: in source — `get_codeblock --file ggml/include/ggml-backend.h --outline` (143 declarations)

| Family | Decls | Lines | Used from (by folder) |
|---|---|---|---|
| Backend scheduler | 14 | L263-356 | src 5, tools/server 2, tests 3 |
| Backend buffer | 12 | L46-73 | ggml/src 30, src 4 |

### What each family is for (one line per family — free text)
- `Backend scheduler` — <|Agent: …|>
```

- **`API: in source — …`** — строка-ФАКТ: сигнатуры и авторские комментарии — в самом файле, вот
  команда. Это и есть «для сигнатур читай `.h`».
- **Таблица семейств** — ФАКТ: сколько объявлений, где в файле, кто снаружи использует (сводка по
  папкам — как свёртка потребителей, Plan08).
- **«What each family is for»** — место для «нафига», по одной строке на семейство, ключ — имя
  семейства. Та же механика, что у работающего «Why these imports are used»: проза переживает
  перештамповку; исчезло семейство — строка уходит в Salvage.
- **Валидно:** маркер `API: in source` в `CARD_FORMAT` (1.3.0) — Public API с ним считается
  заполненным без записей `####`; валидатор проверяет, что названный исходник СУЩЕСТВУЕТ (иначе
  ссылка врёт — ошибка карточки).
- **Когда:** C/C++-заголовки — ВСЕГДА (файл сам есть интерфейс; одно правило на любой размер).
  Реализации (`.cpp/.cu`) — как в Plan08 (записи только для внешних, не объявленных в заголовках).
  Python/TS/C# — без изменений: у них сигнатуры в карточке и есть сжатие.
- Остальное не меняется: `In-Project Dependencies` (+ Kind `conditional(X)`), `## Build facts`,
  проза `How it works` / `Doc links` / `Discrepancies`. Граф и тулы изменения не замечают.

## 4. Семейства — механически, стабильно между штампами

Группировку делает ШТАМП (правка агента была бы перештампована), источники по порядку:

1. **Секции-комментарии автора** — рамка `//` / `// Title` / `//` (проверено: `ggml-backend.h` —
   Backend buffer, device, registry, scheduler…; `llama.h` — Memory, State, Decoding, Vocab…).
2. **Общий префикс имён** (`ggml_rope_*`, `ggml_backend_sched_*`), если разметки нет (`ggml.h`);
   группа — от N записей, остальное — «Other».
3. **Вид объявления** (Functions / Types / Macros) — последний запасной.

## 5. Кэш сканов — данные тула, с проверкой актуальности

- **Где:** `__HQ/tools/_cache/<root-name>-<short hash of the root path>/` — рядом с тулом, как
  `tools/_logs`; подпапка на КАЖДЫЙ корень (одним штабом работаем и по чужим корням). В
  `.gitignore` tools-репо; `deploy_hq` папку не переносит.
- **Что:** по файлу — отпечаток содержимого + результат скана (include-рёбра с условиями, `#if`-зоны,
  объявленные имена; какие имена встречаются в файле — для потребителей).
- **Актуальность — без пересканирования:** `git ls-files -s` (отпечатки всех отслеживаемых файлов
  за доли секунды) + `git status` (изменённые/новые — отпечаток считаем сами); без git — время
  изменения + размер. Совпал отпечаток — данные верны; нет — пересканируем ТОЛЬКО этот файл.
  Удалён — строка выкидывается; новый — сканируется.
- **Полный пересчёт** только при смене отпечатка конфига (`CPP_*`) или версии тула (записаны в кэше).
- **Обратные связи не хранятся** — собираются из прямых при загрузке (всегда согласованы).
- Кэш — ПРОИЗВОДНЫЕ данные, источник правды — исходники: удалили — тул молча соберёт заново.
  Проверку делает сам тул при старте; ни человек, ни агент за кэшем не следят.
