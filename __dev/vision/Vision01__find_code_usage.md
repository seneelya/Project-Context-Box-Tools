# find_code_usage — Vision Contract

## Назначение
Даёт **факт**, а не догадку: кто в проекте реально импортит целевой файл и какие символы из него тянет. Закрывает дыру «consumed surface» — карточка по одному файлу видит только исходящую сторону (что файл экспортит/импортит), но НЕ знает, что из него реально потребляют снаружи. Это входящая сторона, собираемая механически по импортам всего проекта.

## Режимы (через задачу агента)
- **default (downstream consumers)** — ЧТО из файла реально используется вовне = его настоящий внешний интерфейс. Группировка по файлам-потребителям с типом загрузки.
- **`--incoming` (upstream)** — ОТКУДА файл берёт зависимости; внешние пакеты/stdlib сгруппированы как `[external]`.
- **`--verbose`** — ГДЕ именно каждый символ: файл, точные строки, тип загрузки, глубина блока (`lines=[..] levels=[..]`). Это и есть вход для пристрелки `get_codeblock` (см. его Vision).
- **`--tests-only`** — какой API покрыт тестами (сравнение с продовым сканом = непокрытые символы).

Маркеры load-type: `top-level` / `lazy` / `conditional` / `fallback` / `Possible Dynamic import`.

## Связь с get_codeblock
`--verbose` отдаёт `lines=[..] levels=[..]` → агент пристреливается `get_codeblock`-ом и вытаскивает ровно нужный блок, не читая файл целиком. Две руки работают в паре.

## Решения по доводке (locked — сделано)

### 1. Пустые символы — КОРЕНЬ найден и починен ✓
Оказалось симптомом, а не отдельной проблемой. Первопричина: `_get_non_docstring_indices`
(ручной сканер тройных кавычек) помечал ~65% строк живого кода как «докстринг» → реальные
использования молча не записывались по всему проекту; вдобавок alias-доступ добавлялся в
`used_symbols` без гарда → мелькали фантомы из докстрингов/комментов.
**Сделано:** детектор переписан на stdlib `tokenize` (строка = код, если несёт токен
NAME/NUMBER/OP; fail-open при ошибке разбора). `used_symbols` теперь под тем же гардом, что и
`symbol_lines`. Импортированный-но-неиспользованный символ = **зависший импорт**, показывается в
`--verbose` в разделе `# dangling imports` (не пустой строкой). Счётчик `unique symbols` честен.

### 2. Нормализация путей → всегда `/` ✓
**Сделано:** одна точка — `core.rel_path` нормализует `os.sep → '/'`. Чинит все режимы и языки
(весь вывод идёт через `rel_path`). Нативный `\` — только на границе вызова ФС.

### 3. Счётчик саммари = тело ✓
**Сделано:** счётчики берутся из тех же произведённых структур, что и вывод (после `--symbol`
фильтра пересчитываются).

## Реализовано сверх решений
- **Разделение данные/форматтеры:** `core.scan_downstream` / `scan_incoming` отдают чистые
  структуры; форматирование — `report.py`. `main()` тонкий.
- **`--symbol N1,N2`:** пост-фильтр по имени символа во всех режимах (фильтрует данные).
- **`--incoming --verbose`:** по каждому импортированному символу — источник + где он используется
  ВНУТРИ таргета (строки + уровни), вход для `get_codeblock`. Общий хелпер `handler.find_symbol_usages`.
- **Разделы вывода:** `# dangling imports` (verbose), `# external (...)` (incoming).
- **Бонус-баг:** TS `"\n".join` по keepends-строкам двоил переводы строк → номера строк сдвигались; → `"".join`.
  И `import re` во входном файле (был NameError, молча съеденный broad-except, глушивший fast-filter).

## Архитектура (справочно)
`LanguageHandler(ABC)` + хендлеры по языкам (`python_handler` / `ts_handler` / `csharp_handler`), реестр `get_handler(lang)`. regex, не AST. Языки: Python / TypeScript-JS / C#. Дефолты из `CONFIG__TOOLS.py` (`PROJECT_ROOT`, `LANGUAGE`, `TEST_DIRS`), CLI перекрывает.

## Дизайн-решение: symbol-only поиск НЕ встраиваем (композиция, не монстр)
Тул заякорен на МОДУЛЬ (`--file`/`--module`) — отсюда его точность (импорт-резолвинг = ФАКТ
интерфейса). Голый «дай символ, найди везде» без модуля теряет якорь и скатывается в греп (а он
уже есть). Поэтому не новый флаг, а **композиция** (Unix-way):
`grep` (грубо: где символ/в каком модуле) → `find_code_usage --file <модуль> --symbol X --verbose`
(точно: строки + **глубина** уровня) → `get_codeblock --line N --level` (хирургично: только нужный блок).
Ценность за пределами карточек: быстрые level-aware факты «что в файле и на какой глубине зовётся»,
чтобы тянуть блок нужного размера, а не весь файл. Проверено вживую на `test/pythonSRC` (BackendError).
