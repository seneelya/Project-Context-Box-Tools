# get_codeblock — Vision / Contract

## Назначение
Структурный навигатор по исходникам для LLM-агентов. По **строке** возвращает объемлющий её
**блок(и)** с точными границами; или **оглавление** файла. Парсит язык по-настоящему
(tree-sitter / отступы), поэтому точен там, где греп и подсчёт скобок врут. Смысл — **не читать
файлы целиком**: греп даёт строки, get_codeblock превращает строку в «что это и где границы»,
дальше тянешь ровно нужный кусок.

## Текущее состояние — см. документацию, не дублируем здесь
Режимы (`--outline`/`--line`/`--query`), флаги (`--ancestor-level`/`--level`/`--numbered`), языки,
модель блоков и форматы вывода описаны и поддерживаются в актуальном виде:
- `get_codeblock__TLDR.md` — один экран (роутер);
- `get_codeblock__GUIDE.md` — «достаточный» слой (режимы с примерами, воркфлоу агента);
- `get_codeblock__README.md` — полный референс (все флаги, edge-cases, архитектура).

Этот файл — про **намерение, инварианты и развитие**, а не про «как пользоваться».

## Инварианты (контракт — их нельзя нарушать)
- **Одна правда** для глубины: `get_blocks` и `line_level` считают из **одного** набора блоков.
  Глубина, которую видит `find_code_usage` (`levels=`), = та же, что в лестнице `--line`.
- **outline — только именованные блоки** (в JS/TS + стрелки, привязанные к имени); анонимный шум
  в карту не идёт, иначе тонем.
- **Блок = многострочный `{…}`-регион / отступной suite.** Одностроковый `if (x) return;` и
  однострочный `{…}` — не блок. Управляющие блоки в лестнице есть, в outline — нет.
- **Прозрачные рамки** (namespace, `extern "C"`) видны в outline (маркер `.`), но глубины не
  добавляют.
- **Склейка преамбулы**: коммент/докстринг прямо над блоком принадлежит ему; встал на коммент —
  получил блок под ним. Один канонический диапазон блока во всех режимах.
- **Метадата-строки — валидные комменты языка** (`#`/`//`, Markdown — закрытый `<!-- … -->`), не
  мешают парсингу кода. Piped-вывод чистый; человеческие подсказки — только на терминале.
- **Чистый парсер**: get_codeblock ничего не знает про git/сеть/состояние — только структура.

## Философия навигации — «пристрелка», не читая файл
Достать **один самодостаточный блок** из большого (до сотен КБ) файла, не читая целиком.
Вызов без `--query` = **бесплатная пристрелка** (метаданные `level`+`range`+label, токены на текст
не тратятся). Две оси под две задачи, обе «дай больший законченный блок»:
- **`--level 1` (от верха вниз)** — самый крупный самодостаточный объект вокруг точки;
- **`--ancestor-level N` (от строки вверх)** — шаг за шагом расширяем контекст вокруг
  использования/ошибки, когда весь верхний объект избыточен.

Один блок может иметь два адреса (`--level 2` ≡ `--ancestor-level 1`) — не баг, две линзы.
Типовой вход — `lines=[..] levels=[..]` из `find_code_usage`.

## FUTURE (следующие итерации)

### 1. Массив строк на входе — `--line` списком *(главное)*
Греп / `find_code_usage` дают **список** строк. Принять их за один проход (`--lines 5,40,120` или
повтор `--line`) — за один разбор файла блоки для всех кандидатов.

**Нельзя упустить — ДЕДУП.** Если 6 из 10 строк попадают в один блок, `--query` отдаёт его **один
раз**, не шесть. Дизайн: для каждой строки резолвим блок (с учётом `--ancestor-level`/`--level`) →
**дедупим одинаковые** → при вложенности решаем держать оба или схлопывать к внешнему (по
умолчанию — уникальные, перекрытия пометить) → вывод в порядке файла. Это ровно паттерн входа из
`find_code_usage`: один проход, забрать все различные зоны использований.

### 2. `--json` — машинный вывод
Структурированный JSON вместо коммент-строк, когда get_codeblock зовёт **программа** (в т.ч. когда
станет тулом уровня Hermes), а не человек: `[{level,start,end,label,text?}, …]`.

### 3. Унификация лейблов в лестнице
Лейблы в лестнице есть у tree-sitter и Python; **Markdown — без лейбла**. Анонимная стрелка в
лестнице показана `() => {…}`, а в outline — по имени → протащить binding-имя и в лестницу.

### 4. Штамп хеша коммита в заголовок `--query`
Ориентир «протухания» блока. Делать НЕ внутри get_codeblock (чистый парсер), а через **общий
git-хелпер**, которым пользуются и он, и `check_cards_freshness`.

### 5. Отложенные языки (оценены, не сейчас)
- **YAML** — грамматика грузится, но модель ложится плохо: имя-ключ на предке-паре + обёртки
  `block_node`, уровни требуют калибровки (~1-2 ч, не «крохотная спека»). Без большого-YAML боли
  смысла мало — обычно читается целиком.
- **JSON** — нишево: только большой pretty-printed. Часто свалены в одну строку → навигировать
  нечем. **JSONL** — строка = запись, тул не нужен.
